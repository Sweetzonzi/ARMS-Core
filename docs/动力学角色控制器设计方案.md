## 2. 姿态保持：分轴锁转

### 2.1 机制

`setAngularFactor(Vector3f)` 乘在**所有角冲量的入口**上：

- `btRigidBody::applyTorqueImpulse` 是 `m_angularVelocity += m_invInertiaTensorWorld * torque * m_angularFactor`；
- 求解器的接触冲量走的 `btRigidBody::applyImpulse` 在施加角分量前先判 `if (m_angularFactor)`。

坐标：`../Libbulletjme/src/main/native/bullet3/BulletDynamics/Dynamics/btRigidBody.h#applyTorqueImpulse`、`#applyImpulse`。

因此置 0 的轴**对一切角冲量都不响应**，朝向不会被改变。它**不修改逆惯量矩阵本身**——全锁之后实测 `getInverseInertiaLocal` 为 `(0, 4.37, 0)`，即 pitch / roll 两轴为 0、yaw 轴仍有值。传 `Vector3f` 而不是标量因此是必要的。

### 2.2 状态划分

| 状态 | `angularFactor` | 姿态权威 |
| --- | --- | --- |
| 地面站立 / 行走 | `(0, 1, 0)` | 无。锁死，不需要任何姿态控制器 |
| 落地 / 进入地面 | `(0, 1, 0)` + 运动学收敛 | 姿态写入（§3） |
| 飞行 / 悬浮 | `(1, 1, 1)` | 飞行控制层（§4） |
| 布娃娃 | `(1, 1, 1)` | 无 |

`(0, 1, 0)` 的语义是「锁 pitch / roll、留 yaw」：站立必须竖直，但朝向可以自由旋转。因为该因子只按**轴**过滤，绕 Y 轴的角冲量（包括力臂产生的偏航力矩）仍然完整生效。

### 2.3 实测

平地、100 Hz、胶囊几何取自 `common/control/attr/MechaBodyPreset.java#CAPSULE_RADIUS` / `#CAPSULE_HEIGHT`（半径 0.4 m + 圆柱段 1.6 m），质量取自 `common/control/attr/MechaWalkingAttr.java#MASS`（70 kg）：

| 方案 | 初始倾角 | 最大倾角 | 末倾角 | 脚底 y 范围 | 峰值角速度 | 水平位移 |
| --- | --- | --- | --- | --- | --- | --- |
| 锁转 | 30° | **30.00°** | 30.00° | [−0.1072, −0.0010] | **0.000** rad/s | **0.0000** m |
| 旋转全开、无姿态控制 | 30° | 90.66° | 90.00° | [−0.8092, −0.0010] | 3.173 rad/s | 0.8030 m |
| 旋转全开 + PD | 30° | 178.66° | 65.29° | [−0.3504, **+1.0773**] | **28.0** rad/s | 4.118 m |

锁转的倾角恒为初始值、零水平位移、零角速度。旋转全开而不做姿态控制时，胶囊直接倒在 90°。

### 2.4 分轴锁在换形与改质量之后仍然有效

蹲伏 / 卧倒要换碰撞形状，损伤要重建质量与惯性张量，两者都会走原生侧的 `btRigidBody::setMassProps` + `updateInertiaTensor`。这两个函数都不读 `m_angularFactor`（`../Libbulletjme/src/main/native/bullet3/BulletDynamics/Dynamics/btRigidBody.cpp#setMassProps`），因此锁自动保持。实测：`(0, 1, 0)` 锁 + 换形（圆柱段 1.6 → 0.4 m）+ 改质量（70 → 50 kg）+ 绕 X 轴力矩脉冲 1000 N·m·s 之后，倾角仍是 **0.0000°**，pitch / roll 角速度为 **0.000000**，只有 yaw 轴响应（187.5 rad/s）。

这条是蹲伏轮廓与损伤系统能否接入的技术前提。

## 3. 落地处理：首步即锁 + 运动学收敛

### 3.1 为什么锁和摆正是两个独立动作

**锁只负责「不再改变朝向」，不会把已经歪掉的姿态扶正。** 实测：躺倒 90° 的锁转胶囊静置 3 s 仍是 **90.0000°**、角速度恒为 0。

原因是胶囊水平躺地时重力过质心、接触法向也过质心，**合力矩为零**——这是中性平衡，物理上没有任何东西会把它扶正。因此摆正必须由姿态写入完成，省不得。

### 3.2 姿态写入绕过角因子，因此可以在第一步就锁

`PhysicsRigidBody#setPhysicsRotation(Quaternion)` 是直接的位姿写入，不经角冲量通道，因此**不受 `angularFactor` 影响**。实测：落地第一步即 `setAngularFactor(0)`，随后每步做运动学收敛：

| 观测量 | 实测 |
| --- | --- |
| 收敛步数 | 10 步（0.10 s，收敛系数 0.20） |
| 最大倾角 | 30.00°（严格不超过初始值，单调） |
| 末倾角 | 0.0000° |
| 脚底 y 范围 | [−0.0059, −0.0000]（不弹起） |
| 峰值角速度 | **0.0000 rad/s** |
| 水平位移 | **0.0000 m** |

对比「先留自由度做收敛、收敛完再锁」：峰值角速度 0.046 rad/s、水平位移 0.0009 m。首步即锁把求解器在窗口内注入的角速度噪声完全挡在门外，两项都归零。

**这条的工程价值**：一份外部设计思路为落地设计了 `groundWeight ∈ [0,1]` 的平滑过渡、落地前预判（提前把权重提到中间值并缩减比例增益）、以及落地瞬间的角速度吸收。首步即锁成立之后，**这三样都不需要**——没有"逐渐增强的约束"，只有"已锁 + 每步摆正一点"。

### 3.3 收敛律

每物理步：

1. 取当前姿态，解出「只保留 yaw 的竖直姿态」作为目标；
2. 求相对旋转，转成旋转矢量，按系数 `λ` 衰减成一个小角度增量，就地写入姿态；
3. 角速度按同一系数衰减（`ω ← ω · (1 − λ)`）；
4. 倾角小于阈值时清角速度、保持锁转，收敛结束。

角速度衰减不是可选项：即便锁转已经挡住求解器的角冲量，落地那一帧自带的角速度仍在，不清掉会与姿态写入互相打架。

时间尺度由 `λ` 直接给出：λ = 0.20 约 0.10 s、λ = 0.10 约 0.22 s、λ = 0.05 约 0.95 s。**λ 全部取值下过程都严格单调**（最大倾角恒等于初始的 30.00°），因为没有力矩参与，收敛是构造性的。

`λ` 也是「冲击吸收可见度」的调节旋钮：λ 越大立正越快、角速度丢得越干净；λ 越小，落地后"歪一下再站稳"的过程越看得见。角速度在那段窗口里是真正丢掉的。

## 4. 姿态控制为什么不能用地面的 PD：实测

一份外部设计思路用条件启用的 PD 姿态控制器同时满足「地面稳定」与「空中自由」。**空中那一半成立，地面这一半实测不成立。**

同一初态（倾角 30°、静止落地），六组增益（比例增益 500 ~ 20000、微分增益 40 ~ 600）：

```
比例   500 微分  40 → 最大倾角 179.00°，末倾角  12.97°，脚底 y ∈ [-0.2953, +0.7472]，峰值角速度 25.2 rad/s
比例  2000 微分  80 → 最大倾角 178.69°，末倾角  93.75°，脚底 y ∈ [-0.3504, +1.0773]，峰值角速度 28.0 rad/s
比例  2000 微分 200 → 最大倾角 179.89°，末倾角   0.58°，脚底 y ∈ [-0.1936, +0.8655]，峰值角速度 24.2 rad/s
比例  8000 微分 200 → 最大倾角 178.66°，末倾角  65.29°，脚底 y ∈ [-0.3504, +1.0773]，峰值角速度 28.0 rad/s
比例  8000 微分 600 → 最大倾角 178.69°，末倾角 102.41°，脚底 y ∈ [-0.3504, +1.0773]，峰值角速度 28.0 rad/s
比例 20000 微分 400 → 最大倾角 178.66°，末倾角  65.05°，脚底 y ∈ [-0.3504, +1.0773]，峰值角速度 28.0 rad/s
```

六组全部先翻过头（178.66°–179.89°）、全部被弹离地面（脚底升到 +0.75 ~ +1.08 m）、峰值角速度 24–28 rad/s，末倾角散在 0.58° 到 102° 之间没有规律。

**机制**：胶囊只通过**一个**接触点与地面作用。任何绕质心的回正力矩都无法产生「把接触点移回质心正下方」的效果，反而主动把接触点甩到质心侧面；接触法向力随之出现向上的分量，胶囊起飞；离地后没有摩擦，进入自由翻滚。这是单接触点拓扑的固有形态，**不是调参问题**——站立所需的「过程有界」做不到。

落地前预判（提前介入）也帮不上：起飞发生在回正力矩起作用之后，不是介入时机的问题。

### 4.1 两条实现约束（无论 PD 最终落在哪一层都要遵守）

- **角加速度必须限幅。** 微分项对求解器接触噪声做线性放大是**正反馈**。不限幅时实测角速度在 2 s 内涨到 `1e36 rad/s`、比例项输出无穷大（`applyTorque` 抛 `torque must have all components finite`）。
- **逆惯量为 0 的轴必须跳过。** `α / invInertia` 在锁死的轴上会得到无穷大。这个除法本身就是「该轴是否可施力」的判据。

## 5. 力产生机制：三种约束形式

### 5.1 分类

按**力从哪来**分，而不是按底盘外观分：

| 机制 | 约束形式 | 是否可用「本体轴包络」表示 |
| --- | --- | --- |
| **接触型**（双足、轮足、履带） | **摩擦锥** `\|F_t\| ≤ μN`；接触力**单向推**，方向由落脚点与地面几何决定 | **不能**。本体坐标系里没有"落脚点"，力方向取决于这一步脚踩在哪 |
| **推进型**（悬浮、飞行推进器） | 各轴推力上下界 | **能**，这是包络的正确适用域 |
| **气动** | 依赖速度、姿态、来流方向、部件遮挡 | **不能**，见 §6 |

轮足与履带是同一套差速模型的两种装配形态，差异在「力如何映射到各轮」而不在约束形式，因此它们与双足同属接触型，共享摩擦锥约束。

**接触型控制力保留**：地面行走、轮式 / 履带驱动一律走接触层，由角色控制器给出平面控制力，受摩擦锥钳制。

### 5.2 三种机制的力各自拥有，不要求和成一个

一份外部设计思路把所有移动方式统一为「推力贡献者」，输出力与作用点、汇总为合力与合力矩，再由推进器包络钳制。**接口统一是有价值的**（不同底盘、不同配装、不同损伤状态接入同一套通道），但**统一后的力不能统一受包络钳制**——上表的约束形式不同。

正确的分工是三条通道各自拥有力：

```
① 角色控制器 → 平面控制力（接触型），受摩擦锥钳制
② 接触求解器 → 法向力 / 摩擦冲量（接触型），由引擎自己算
③ 飞行包络   → 各轴推力（推进型），配装期定界、运行期钳制
④ 气动       → 独立通道，见 §6.4
```

其中 ② 尤其不要手工预生成：地面反力由接触层自己的求解器给出，角色控制器预先算一份"腿力"再让求解器重解一遍就是同一次接触被算两次。

## 6. 气动力：复用既有系统 + 独立通道

### 6.1 现状

`../Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/SubPart.java#prePhysicsTick` 已经在每物理步为每个流体动力计算点算气动力，用的模型是**一阶 + 二阶双项**：

```
一阶（粘性）：  F₁ = viscosity · c₁ · |v| · wettedArea
二阶（惯性）：  F₂ = 0.5 · density · c₂ · |v|² · projectedArea
```

坐标：`../Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/util/mechanic/DynamicUtil.java#applyAxisDrag`。

要点：

- 系数是**每个方向一对**（一阶 / 二阶），六个方向各自独立：`forward` / `backward` / `leftward` / `rightward` / `upward` / `downward`，默认 `[0.1, 1.0]`（`../Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/attr/HydrodynamicAttr.java#DEFAULT`，字段含义见同文件 `#forward` 一族的 Javadoc）；
- **逐轴各向异性已经存在**：`DynamicUtil.java#applySimpleDragAllDirections` 对三轴分别使用 `projectedArea.x/y/z`，即各轴的参考面积可以不同（`SubPart.java#projectedArea`，由 `../Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/Part.java#calculateProjectedArea` 自动计算，也可由 `SubPartAttr#projectedArea` 显式配置）；
- 还有跨音速增益（`HydrodynamicAttr#transSonicAmplifier`）、升力（简易 `xLift` / `yLift` / `zLift`，或 `HydrodynamicAttr#advancedAero` 的升力线模型带失速裁剪）、以及**部件互相遮挡**（沿来流方向射线，按 `SubPartAttr#hydroPriority` 判定谁遮谁，`SubPart.java#prePhysicsTick` 内的 `occlusion` 一段）；
- 施加方式是 `../Spark-Core/src/main/java/com/jme3/bullet/objects/PhysicsRigidBody.java#applyForce`（力 + 作用点），**力臂自然产生力矩**；
- 只在服务端、且速度平方超过 0.01 时计算（即 |v| > 0.1 m/s 以下无气动）。

气动系统的设计说明见 `../Machine-Max/docs/wiki/4-物理与战斗机制/4.2-流体动力学与气动.md`。

### 6.2 结论：不另建一套

「让所有 SubPart 每物理步算气动力」这个方向已经落地，因此**不需要新增气动模型**。需要定的是它与其他力通道的关系，即 §6.4。

### 6.3 折进包络为什么不可行

一份外部设计思路提出两个候选：把气动**并入可用控制力**（作为包络的偏置），或**保持分离**（作为前馈）。先把偏置法算清楚。

设某轴推进器配置为 `F ∈ [0, 1000] N`（单侧推进器），当前该轴阻力 `D = 500 N` 且与速度反向：

| 速度方向 | 偏置后的可用区间 | 问题 |
| --- | --- | --- |
| 沿 +轴 | `[0 − 500, 1000 − 500] = [−500, 500]` | 下界变成 −500，但**没有反向推进器**，这个负值是假的 |
| 沿 −轴 | `[0 + 500, 1000 + 500] = [500, 1500]` | 上界超过引擎能力 500，**执行层做不出来** |

即：偏置法让区间的两端**同时**失去物理意义（一端是假的、一端不可实现）。根本原因是它把「环境施加的力」与「引擎能出的力」混进了同一个区间。

除此之外还有三条更硬的理由：

1. **升力不是阻力。** 升力垂直于来流，不可用"沿速度方向的偏置"表达；带倾角时升力可以指向侧向甚至向下，标量偏置编码不了。
2. **偏置是速度平方的、包络是常数。** 上面的 `[−500, 500]` 只是当前速度下的瞬时值，速度一变整个区间就变了，包络随之每步变形状——而包络本该是配装期确定、运行期缓变的能力描述。
3. **每轴独立假设在斜流下失效。** 气动系数是按流体动力计算点本地坐标系的六个方向给的，而气流相对本体是任意方向；斜流下 Z 轴的阻力耦合进 Y 轴，包络的对角结构保不住。

### 6.4 保持分离，作为前馈

标准形式：

```
F_out = F_ff + F_fb
F_ff  = −F_aero_model(v, attitude)           气动预测，前馈抵消
F_fb  = m · aDes + K_p · e + K_d · ė         反馈，只处理未建模部分
```

前馈优于偏置的关键在**误差的去向**：

| 做法 | 模型不准时的后果 |
| --- | --- |
| 折进包络 | 包络是**权限**。预测偏差直接吃掉机动权限——连"想出的力"都出不了 |
| 独立前馈 | 偏差只是**残余扰动**。控制器仍有全部权限去纠，只表现为跟踪误差 |

前馈的精度要求也不高：只要把扰动压到反馈带宽以内，剩下的由反馈处理。而 SubPart 的气动模型本来就在每物理步跑，**预测是免费的**——这是 §6.2 的直接收益。

### 6.5 前馈基准的取向（待定）

前馈把气动**预**抵消掉了，于是「损伤后自然失衡」这个期望表现会被压掉一部分：如果前馈用的就是当前（已损伤）的气动模型，那它补偿的是"现在真实的气动"，失衡被主动纠正。

因此要明确一个取向：

- **失衡作为表现** → 前馈只能用**未损伤的基准模型**，让损伤造成的那部分偏差留给反馈去纠（纠不动就是失衡）；
- **抗扰优先** → 前馈用当前完整模型。

这不是技术选择而是手感选择。它同时决定飞行控制层的增益该多大，因此与 §7.2 绑在一起。

## 7. 待议与暂不展开

### 7.1 接触型推力的具体实现

保留接触型控制力已经确定（§5.1），但**具体如何产生**未定。一条已识别的分歧：一份外部设计思路的通用管线写的是速度伺服（`aDes = clamp(vErr / accelTime)`，积分型），双足那一节写的是直接给定落脚点反力（`F_leg = mass·(aDes + g) / supportCount`）。这两者是不同的物理层语义，混在一层会打架。需要先明确：接触型输出的究竟是**接触点上的力**（受摩擦锥约束），还是**期望速度**（由控制器去追）。前者是物理层定义，后者只是实现手段之一。

### 7.2 飞行控制层

PD 姿态控制归飞行控制层，但该层本身（意图 → 力矩的完整路径、增益整定、与推进器包络的关系）**暂不展开**。§4.1 的两条实现约束在该层同样适用。

### 7.3 力学质量与碰撞质量

`Δv = I / m` 里的 `m`（闪避见 `common/control/MechaCharacter.java#requestDodgeImpulse`，跳跃见同文件 `#updateJump`）该取控制器质量还是刚体系统总质量；控制器的碰撞质量与力学质量是否同一个值。两项都要等躯干刚体接上才能定，见 `docs/刚体角色控制器原型验证与实施计划.md` §7.3。

### 7.4 摩擦模型

接触摩擦由引擎接管之后，力模型里三处摩擦项的落点变化见 `docs/刚体角色控制器原型验证与实施计划.md` §6。该节末列出的讨论范围（`MOVE_SPEED_MODIFIER` 的等比性、低摩擦地面、引擎切向约束与沿向积分是否互相抵消、滚动摩擦与湿滑是否接入）**全部仍未定**。

### 7.5 速度相关阻力不能有三套

现在有三个速度相关阻力项：气动一阶项（§6.1）、`common/control/attr/MechaWalkingAttr.java#C1`（映射到 KCC 的 `setLinearDamping`，当前值为 0）、以及一份外部设计思路的通用管线里的 `drag` 项。**同一台机娘身上三套阻力是等着出错的**，应统一到气动系统这一套（即删掉 `C1` 的映射与通用管线里的 `drag` 项，速度相关的耗散只由 §6.1 的一阶与二阶项给出）。

### 7.6 默认气动系数对行走的影响（待确认，非实测）

用当前默认系数与一组假定值粗算：`c₂ = 1.0`、`density = 1.29 kg/m³`、`projectedArea ≈ 0.5 m²` 时，6 m/s 的二阶阻力约 11.6 N，作用在 70 kg 上约 **0.17 m/s²** 减速度。与之对比，地面低速区的控制力加速度量级约 8 m/s²（`common/control/attr/MechaWalkingAttr.java#F_MAX` / `#MASS`），因此默认气动系数对行走几乎无影响。

**这条是参数估算而非实测**，`projectedArea` 的取值是按机娘尺度假定的，实际值由 `Part.java#calculateProjectedArea` 从模型算出。要以实测换掉这个数，需要在真实装配体上取一次。

另外遮挡检测的 `HydrodynamicAttr#effectiveRange` 默认 **1.0 m**，即 1 m 内的同装配体部件默认会互相遮挡。该默认值是按载具尺度给的，机娘的部件间距是否落在同一量级需要确认。
