# 控制分配：作动器 wrench 分配设计

> **本文是什么**：把「这一步我想要这样一份合力与合力矩」翻译成「每个作动器出多少」的那套机制。它是一条**纯函数**：输入是各作动器的雅可比列与界、分配目标、权重与正则化系数，输出是归一化控制量 `u`（油门 / 偏角）。不碰 `PhysicsSpace`、不需要活着的世界、不依赖载具类型——机娘与固定翼共用同一份解。
>
> **本文不是什么**：不写角色控制器的姿态自由度、落地处理、接触摩擦与速度语义（那些见 `docs/角色控制器-刚体动力学方案.md`）；不写气动模型本身（见该文 §10）；不写引擎允许什么（见 `docs/角色控制器-刚体原型与引擎约束.md`）。

## 1. 四类驱动，两个去向

分类判据是**控制器能不能命令它**——也就是这个力源有没有一个**可命令的致动器状态**：

| 类型 | 可命令量 | 力由什么决定 | 典型例子 |
| --- | --- | --- | --- |
| **推进器** | 出力（油门） | 指令，与速度、姿态**无关** | 喷射推进、悬浮 |
| **接触型** | 落脚点选择 | 指令 + 接触状态（受摩擦锥限制） | 双足、轮足、履带 |
| **固定零件气动** | **无** | 完全由当前运动与姿态决定 | 机翼、机身、尾翼 |
| **舵面气动** | 偏转角 | 指令 + 动压 `q = ½ρv²` | 副翼、升降舵、方向舵 |

**有可命令量的一类进分配器，而且是同一个分配器。** 推进器、舵面、以及被当作减速板用的气动面**全部是同一件事**：各有一个可命令量 `u`，各对刚体贡献一份力与一份力矩。它们之间的差别只落在两份数据上——每个作动器的**界**（§2.2）与它的**雅可比列**（§3）——而不是落在几条不同的处理路径里。分配问题不区分器件的「类型」，只读这两份数据。

减速板因此不是第五类，而是舵面的一个特例：可命令量同样是偏角，只是外形让它的雅可比列偏向沿来流方向的力而不是力矩。这件事由列自动表达，不需要类型标记。

接触型也产出一份力，但它的方向不是安装出来的——本体坐标系里没有「落脚点」这个量，写不出固定的列（`docs/角色控制器-刚体动力学方案.md` §9.5），因此留在分配器之外。

**没有可命令量的一类去目标上的矢量减法。** 固定零件气动的力完全由当前运动与姿态决定，控制器无法支配它；环境已经把它给了刚体，于是控制器的任务是**减掉它**：期望净 wrench 减去这一份，剩下的才是作动器要凑的量（§2.1）。这个去向不是「另加一股力」，而是**同一个目标上的减法**；完整算式与三条路的对比见 `docs/角色控制器-刚体动力学方案.md` §10.4、§10.6。

**「固定零件」与「舵面」按可命令量划分，不按外形或安装位置划分。** 同一片翼面，作为固定零件时装它就完全不参与控制、只被减掉；装上作动器后它就成为舵面。判据是那台作动器，不是那片翼面。

## 2. 作动器数据与分配目标

### 2.1 目标的语义

```
w_des    = 刚体的期望净 wrench（控制层的意图）
w_known  = 一切不由本控制器作动器提供、但已知的 wrench
           （固定零件气动、舵面 δ=0 基准项、重力、其它可测的已知扰动）
分配目标 w_alloc = w_des − w_known          ← 矢量减法
```

**`w_des` 的语义钉死为「刚体的期望净 wrench」**，否则这条减法无从写起：环境已经给了刚体的那一份必须先从目标里减掉，剩下的才是作动器要凑的量。

**`w_known` 是被减项，不是被遗忘项。** 施加的永远是各力源的实际力（`docs/角色控制器-刚体动力学方案.md` §8.1 的单一施加点），`w_known` 只是从**需求**里预先扣掉，不会改变任何一份实际力的归属。

**为什么是减法而不是「在输出上再加一股抵消力」**：手工合力再 `applyCentralForce` 之后，**引擎不会替我们检查这个力作动器出不出得来**，因此加在输出上会凭空造力；而减去之后，这份需求会进入分配器的饱和判断，缺口与 windup 回退全都自洽。完整论证与反例见 `docs/角色控制器-刚体动力学方案.md` §10.6。

### 2.2 各作动器的界

| 来源 | 界的形状 | 什么时候变 |
| --- | --- | --- |
| **推进器** | `u ∈ [0, 1]`（归一化油门，单侧） | 方向是配装期常数；大小随推力包络、损伤、燃料变 |
| **舵面 / 减速板** | `u ∈ [−1, +1]`（偏角 / `δ_max`，双侧） | 形状配装期定死，模长随动压 `q` 缩放（§2.3） |
| **接触型** | 不进分配器 | §1 |

**两个端点都要给，而且不必对称。** `[0, 1]` 说的是「这台推进器只能推不能拉」，不是「油门关不小」；`u = 0` 永远在界内，因此**零出力永远可达**。这条在分配层表现为一个不变量：`w_alloc = 0 ⟹ u = 0`（§7）。

**界与雅可比列合起来才是能力。** 界说明「能推多远」，列说明「推一单位得到什么」。两者都按当前状态取，所以「舵面的能力随速度变」不需要任何特判——低速时它的列模长趋零，分配器自然不会用它（§3.1）。

### 2.3 从零件到作动器数据

一个**作动器**是「有一个可命令量、并对刚体贡献一份力与一份力矩」的对象。它对分配器只需要交出四样东西：

| 项 | 内容 | 从哪来 |
| --- | --- | --- |
| **可命令量 `u` 的界** | `[u_min, u_max]`。归一化后大多是 `[0, 1]`（油门）或 `[−1, +1]`（偏角 / `δ_max`） | 零件属性与当前状态，见 §2.2 |
| **雅可比列 `J_k`** | 该作动器的 `u` 变化一单位对合力与合力矩的贡献 | §3 |
| **作用点 `p`** | 世界作用点，用于算力臂 | 定位点的世界位姿 |
| **力函数** | `u → (p, F)`，代回复核要用（§7） | 该器件自己的模型 |

映射分三层，每层对应作动器的一类信息：

| 层 | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| **位置 → 力臂** | 定位点的世界位姿 | 该点相对刚体质心的位移 `r = p − c` | 决定这份力**能产生多大力矩** |
| **姿态 → 方向** | 定位点的世界旋转 | 力在本体坐标系下的方向 | 决定这份力**落在哪一轴**，也决定雅可比列的方向 |
| **属性 + 状态 → 大小** | 零件属性（最大出力、响应时间、能耗）与状态（接触 / 动压） | 该作动器当前能出多大 | 决定 `u` 的界，也决定雅可比列的模长 |

**力臂 `r` 必须每物理步按实际位姿重算**，不能在配装期缓存。零件之间存在约束余量、损伤与相对运动，这与「安装朝向只在配装期算一次」不是一回事。

**界的来源分两种：配装期定死形状，运行期缩放。** 推进器的**方向**是配装期常数，**大小**不必是——推力包络随高度与空气密度、损伤、燃料变化。分配器只需要当前值，所以这一点不构成负担。舵面的界由**最大偏角** `δ_max` 在配装期定死形状，运行期**随动压 `q` 缩放**：

```
该作动器在某方向能出的力 = q 决定的比例因子 × ( 最大偏角下的力在该方向上的分量 )
```

**力矩的可达范围不能从力的范围导出。** 每个作动器的力矩是它的力与力臂的叉积 `(p − c) × F`，这套关系写在雅可比列里（§3.1），不是另一组独立的界。参考点全场唯一为刚体质心。

## 3. 雅可比 `J`：割线列

### 3.1 两类列的取法

**推进器的列是配装期常数。** 力沿安装方向、大小与 `u` 成正比：

```
J_k = [ d ; (p − c) × d ] · F_max        d = 安装方向（本体坐标系），F_max = 当前满油门推力
```

`r = p − c` 每物理步按实际位姿重算（§2.3），代价是一次叉乘。`F_max` 取当前值，因此推力包络、损伤、燃料都能体现。

**气动面的列只能数值求导，而它几乎免费。** 气动力函数的入参里**没有偏角**——偏角是通过定位点自身坐标系的旋转、改变局部来流角进入的（`../Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/util/mechanic/DynamicUtil.java#advancedAeroForce`）。因此列这样取：

```
J_k = ( w(u_k = u_max) − w(u_k = 0) ) / u_max
```

**用界上的割线，不用切向导数。** 割线在 `u = 0` 与 `u = u_max` 两端**严格精确**，误差只剩区间内的曲率。切向导数要在工作点两侧对称差分，既多一次求值、又丢掉端点精确性。

**两个端点精确是个有用的性质**：它保证「零偏角 = 零控制力」与「满偏角 = 满控制力」两条语义都严格成立，因此 §7 的零出力不变量与饱和判断都落在精确点上。

**成本可以忽略，因为贵的那一步与偏角无关：**

| 步骤 | 成本 |
| --- | --- |
| 遮挡 `rayTest`（JNI 往返） | 每 tick 每个气动点**一次**，与偏角无关，求导时复用 |
| 力函数本体（`atan2` + 约 40 次浮点） | 每列多一次 |
| 射线方向随偏角转动的误差 | 遮挡半径默认 1.0 m，`δ_max = 25°` 时射线端点横移约 0.42 m；只在有零件落在这段距离内时才有影响，且误差是**乘性因子** |

按 8 片舵面 × 2 个定位点估，每 tick 多的开销在微秒量级，100 Hz 下是噪声。

### 3.2 割线的实测精度

**截距与斜率是每拍重取的，不是配装期标定值。** `w_aero(0)` 与 `J_k` 都与偏角无关，但与**当前工况**有关，因此同样每物理步现算：

| 重算的输入 | 影响哪一部分 |
| --- | --- |
| 当前速度（气动场合含 `ω × r`，逐计算点） | 两者。它决定攻角，因而决定 `cl`、`cd` 与动压 `q` |
| 当前位姿（`p` 与坐标系朝向） | 两者。它决定力臂 `(p − c)`，也决定力的方向落回本体坐标系后是哪一轴 |
| 当前遮挡因子 | 列的模长。它是个乘性因子，与偏角无关，所以求导时复用 |
| 当前气动系数（损伤、构型） | 两者。翼面被打坏后 `cl` / `cd` 直接变，不需要另设「损伤模型」 |

**三遍力函数共用同一套输入，因此「重算」不会让三份数据互相矛盾**：截距用 `u = 0` 那一遍，割线用 `u = 0` 与 `u = u_max` 两遍之差，复核用实际 `u` 那一遍（§7 的链条）。**每列多跑一遍力函数，成本在微秒量级**（§3.1）。

**误差量级由该器件的力函数决定，只能实测。** 以气动面为例（系数取 `../Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/attr/AdvancedAeroAttr.java#DEFAULT`、`V = 25 m/s`、参考投影面积 1.0 m²、`δ_max` = 25°，列模长 1118 N）：

| `δ` | 误差占列模长 | 误差绝对值 |
| --- | --- | --- |
| 0° | **0** | 0 N |
| 2° | 2.2% | 24.5 N |
| 5° | 4.8% | 53.4 N |
| 10° | 7.2% | 80.3 N |
| 12.5°（区间正中） | **7.5%** | 83.8 N |
| 15° | 7.2% | 80.5 N |
| 20° | 4.8% | 53.9 N |
| 25° = `δ_max` | **0** | 0 N |

误差在两端精确为零、在区间中点取峰值，形状近似 `4t(1−t)`（`t = δ / δ_max`）。**7.5% 这个量级不需要设阈值去防**，理由是结构性的：分配器的输出是**净 wrench 指令**，它经力函数与接触层回到刚体的加速度，环路上因此带一个增益近似为 1 的反馈——几 % 的增益误差只影响收敛速度，不影响收敛性。力函数的真实形态与两个曲率来源的相消关系见 `docs/角色控制器-刚体动力学方案.md` §10.3。

## 4. 问题的形状

每个作动器**只有一个可命令量** `u_k`（推进器的油门、舵面的偏角），而它一次同时决定一份力与一份力矩。所以真实可达集不是「一个 3 维力盒加一个 3 维力矩盒」，而是 6 维 wrench 空间里由 `N` 条一维曲线张成的集合。

把每条曲线在当前工作点线性化，就得到一张矩阵：

```
列 k = 该作动器的 u_k 变化一单位，给刚体带来多少力与多少力矩
```

分配问题于是写成

```
J u ≈ w_alloc      J: 6×N（按 §8 可降维）    u: N 个可命令量
u_min ≤ u ≤ u_max  逐作动器的界（§2.2）
```

**这样写的直接好处**：`J` 的列空间就是可达的 wrench 集合，解出的 `u` 对应的 wrench 必然落在里面——「命令的力出不来、命令的力矩出不来」不会成为需要事后发现的缺口，它就是问题的定义本身。力与力矩也不可能被独立钳制，因为它们由同一个 `u` 一起产出。

**这里没有「器件类型」这个概念。** 推进器、副翼、升降舵、减速板**都是列**。减速板不过是「力矩行小而力行大」的列，副翼是反过来的列。§6 说明为什么不需要给它们分类。

**推进器并入同一个解，换来一条跨速度包线。** 低速与悬停时气动列的模长趋零，只剩推进器列可解；高速时反过来。**同一个解在低速是推力混合器、在高速是气动控制器，中间连续过渡**——没有模式机、没有配平表、也没有「速度不够舵效失效」的特判。代价只是把推进器也写成列（§3.1）。

**附带收益（一）：气动面的力变成已知量。** `u` 是分配的输出，因此该偏角下的气动力**是算出来的，不是预测的**——前馈一侧只需要承担 `u = 0` 的截距（`docs/角色控制器-刚体动力学方案.md` §10.3）。

**附带收益（二）：控制量本身就是程序性动画要的那个量。** `u` 恰好是显示层的原始输入——推进器的 `u` 就是油门（尾焰大小、音效强度、粒子发射率），舵面的 `u` 乘以 `δ_max` 就是偏角（模型姿态）。三点具体好处：

| 好处 | 为什么 |
| --- | --- |
| **物理与动画同源** | 动画用的是分配器算出的那一个偏角，不是另按输入猜一个，因此不存在「模型显示 30°、物理用的是 18°」这种漂移 |
| **饱和看得见** | `u` 已经过级联钳制，撞界时尾焰会**真的到顶**、舵面会**真的停在 `δ_max`**——玩家直接看得出这台机器没权限了，不需要另做一套提示 |
| **诊断可可视化** | §5.1 的残差（饱和缺口）与 `u` 一起画出来，就能把「哪些方向没满足、差多少」直接摆在调试界面上 |

按 §6 的做法就没有这一份：那里分配出来的是**逐轴力**，偏角得从力反解，而且同轴多面之间存在剩余自由度、要另定一条分担规则。**分配器把「反解偏角」这一步整个省掉了——`u` 就是答案，不是中间量。** 这份输出怎么送到渲染侧，见 §9。

## 5. 求解：阻尼伪逆

带界的加权最小二乘没有闭式解，因此分两步：先解无界的加权伪逆，再处理越界（§5.1）。无界解取**阻尼最小二乘**（Tikhonov 正则）：

```
min ‖J u − w_alloc‖² + λ² · uᵀ W u
```

用 push-through 恒等式把解换到行数那一侧：

```
u = ( JᵀJ + λ²W )⁻¹ Jᵀ w_alloc
  = W⁻¹Jᵀ ( J W⁻¹ Jᵀ + λ²I )⁻¹ w_alloc
              └── 只有 6×6 或更小（§8） ──┘
```

`N`（作动器个数）通常大于 6，所以取右边那条：**要分解的永远是 6×6 或更小**。

**`λ > 0` 让这个矩阵恒为正定**，于是：

- 分解永远成功，不需要选主元、不需要判秩；
- 级联去掉若干列之后约化系统**照样可解**——这是 §5.1 那条「约化后可能减秩」的根治办法，不是补丁；
- 同构列（几片几何对称的舵面，`J` 的列几乎相同）那份量级可达 `10⁵` 的相互抵消解被 `λ` 直接压住。

**`λ` 怎么取。** 先把行按 §5.2 的第一职责归一化，使 `J W⁻¹ Jᵀ` 的对角元落在 1 量级，然后取

```
λ² = ρ · mean(diag(J W⁻¹ Jᵀ))        ρ 从 1e-4 起调，量级范围 1e-6 ~ 1e-2
```

物理含义是「**多小的奇异方向允许被激发**」，并且它给出命令放大的硬上界：`‖u‖ ≲ ‖w_alloc‖ / λ`。`ρ` 是纯数字、与配装无关，可以直接做成配置项。全程用 `double` 而非 `float`——正规化把条件数平方了，`double` 下 `κ(J)` 到 `1e6` 仍够用。

**计算量**（`N ≈ 10`、6 行）：组装 `J W⁻¹ Jᵀ` 约 420 次乘加、6×6 Cholesky 约 56 次乘加加 6 次开方、前代回代约 72 次、`u = W⁻¹Jᵀ y` 约 60 次——**合计不到 1000 次浮点运算**，每物理步一次。

**不需要线性代数库。** 需要的是 6×6 以内的小型对称正定 Cholesky 分解（实际维度由调用方给的行掩码决定，见 §8），约 40 行。可用的库都存在，但都不划算：

| 方案 | 情况 | 判断 |
| --- | --- | --- |
| Apache Commons Math 3.6.1 | `SingularValueDecomposition#getSolver()` 返回的 `DecompositionSolver#getInverse()` 就是 Moore–Penrose 伪逆，能完成任务 | 2 MB 量级的依赖；`RealMatrix` 面向对象，每次调用都分配对象，在 100 Hz 循环里是纯 GC 噪声。而且本问题**不需要 SVD**：`λ > 0` 已经保证可解，截断奇异值只是 `λ` 的一个替代品 |
| EJML | 有 `SolvePseudoInverseSvd_FDRM` 一类现成实现 | 同为外置依赖；为 6×6 拉一个 1–3 MB 的 jar 不划算 |
| JOML | Minecraft 1.19.3+ 已在类路径上，不需要额外依赖 | **没有 Cholesky、也没有 SVD**，只有 2/3/4 维矩阵，解决不了本问题 |
| **手写 Cholesky** | 约 40 行 | 推荐 |

**可测性是这个选择的另一半理由。** 整个分配器是一个纯函数 `(J, 界, W, λ, w_alloc) → u`，不碰 `PhysicsSpace`，因此下面这些都能在 JUnit 里逐条验证，不需要活着的世界：

| 断言 | 内容 |
| --- | --- |
| 可达即达成 | `w_alloc` 落在可达集内时 `Ju ≈ w_alloc`，残差远小于 `‖w_alloc‖` |
| 不可达时残差即缺口 | `u` 逐项不出界，且 `‖w_alloc − Ju‖` 等于饱和缺口 |
| 对称冗余等分 | 两列完全相同时两者的 `u` 相等 |
| 零指令不点火 | `w_alloc = 0 ⟹ u = 0`（§7） |
| 简并被压住 | 近简并配装下 `‖u‖` 被 `λ` 限制在 `‖w_alloc‖ / λ` 量级内 |
| 门控行不产生虚假缺口 | 活行之外置零之后，残差不受影响（§8） |

### 5.1 饱和处理：级联，不追最优

伪逆解出 `u` 之后撞界怎么办。**不做二次规划、不做活跃集迭代，只用级联**：

```
① 解 u = W⁻¹Jᵀ(JW⁻¹Jᵀ + λ²I)⁻¹ w_alloc
② 取出所有越界的作动器，各自钉在它撞到的那个界上   ← 一次全取，不必逐个
③ w' = w_alloc − J_固定 · u_固定                 ← 目标减去它们已经提供的量
④ 用剩下的自由列重解 → 回到 ②，直到没有越界为止
⑤ 收尾：核一遍已钉列的乘子符号（可选，见下）
```

**终止性不成问题。** 每轮至少钉住一列、而且**永不释放**，所以最多 `N` 轮。单侧界（推进器那类 `[0, 1]`）也一样：钉在 0 上就是「这台不点火」，把它移出自由集是一次合法的集合缩减，残差照实报出来。

**为什么一次全取是安全的。** 带界约束最小二乘的 KKT 条件就是「活跃集内取边界值 + 其余解无约束最小二乘」。把同时越界的作动器一起钉死、一起移出自由集，正是活跃集法处理「一次迭代中多个约束同时活跃」的标准做法。而且**去掉饱和列之后可行集变大，残差 `‖Ju − w_alloc‖²` 单调不升**。

同构列（例如左右副翼几何对称到极致）的情形下更干脆：`J` 里两列完全相同时，伪逆给两者的分配**必然相等**，它们本来就一起饱和、一起被钉。逐个丢反而要走一圈无用的路。近简并时同时丢弃还有额外好处——它**一次消掉那条病态方向**（§5 里那份 `10⁵` 量级的抵消解），逐个丢则要把这份大数在自由集里过一手。

**不追最优的代价，明确记账。** 级联是贪心的（钉上就不再回头），因此不保证得到 KKT 点。一个两作动器、两维 wrench 的反例：某组 `J` 与 `w_alloc` 下贪心给出残差 `1`，而精确 KKT 解是 `0.91`——**差约 8%**，原因是正确的活跃集需要**释放**已钉的作动器、改钉另一个。

**接受这个差距，理由是它会被回路吃掉**：

- 偏差表现为**当拍未达成的 wrench**，下一拍反馈继续纠；
- 它**无偏**——不会系统性偏向某个轴，因此不积分、不漂移。偏差随残差一起被报出来，而残差正是 windup 保护的输入；
- 反过来，精确解要引入释放逻辑、循环保护与终止判据。**多一套会出 bug 的机制，换一个玩家感知不到的改善，是负收益。**

**第 ⑤ 步的收尾检查是可选的，而且零迭代增量。** 残差 `r = J_自由 u − w_alloc` 在解最小二乘时**本来就是副产品**，因此乘子

```
λ = J_固定ᵀ r           λ_k 符号与 u_k 所钉的界不符 ⟹ 该列被错误地钉住
```

只需一次 `N×6` 的矩阵向量积（`N ≈ 10` 时是 60 次乘加），比一次 `6×6` 分解便宜得多。它**不释放、不重解**，只把结论记进下面的缺口输出。

**残差本身就是「饱和缺口」，是本方案的有用输出。** `‖w_alloc − Ju‖` 与它的方向直接给出「哪些方向没能满足、差多少」，正好喂给调用方的 windup 保护（按 `实际出力 / 期望出力` 回退积分），不需要另设一套饱和判据。调用方侧那一条的落点见 `docs/角色控制器-刚体动力学方案.md` §9.6。

**缺口是相对于 `w_alloc` 算的，不是相对于 `w_des`。** 这一点自动把**配平需求**排除在缺口之外：悬停顶重力、巡航顶阻力都是 `w_alloc` 之内的正常需求，不是饱和。`/arms` 的 dump 要能区分这两者。

**一处必须留意的求解失败**：去掉若干列之后，**约化后的系统可能减秩**（尤其近简并列被丢之后）。这跟「丢几个」无关，但它是级联法真正会崩的地方——解出垃圾而**没有地方会报错**。对策与 §5 里的 `λ` 同源：对约化系统同样加 `λ²I`，可解性由构造保证。

### 5.2 权重矩阵 `W` 的两层职责

`W` 出现在 `u = W⁻¹Jᵀ(JW⁻¹Jᵀ + λ²I)⁻¹w_alloc` 里，是 controller effort 二次型的**代价**矩阵。它的两个职责要分开设，别用一个数同时干两件事。

**第一职责（必须）：把力与力矩拉到可比尺度。**

`J` 的前三行是力（N），后三行是力矩（N·m），两者数值尺度差着质量与惯量的量级。不归一化的话，伪逆会隐式地把「1 N 的力误差」与「1 N·m 的力矩误差」当成同等重要——而按机娘当前的几何，绕 Y 轴转动惯量约 4.4 kg·m²，**几十 N·m 就能把姿态甩飞**，两者根本不等价。具体系数要在真实配装下量一次（§10.1）。

**第二职责（按表现定）：决定冗余时谁多干一点。**

`W_i` 越大表示该机构越「贵」，分到的量越少。所以「让大机构多出力」要给它们**小**权重。但要说清它能做到什么、做不到什么：

- 它分配的是**「在多个机构都能干这件事时，谁来干」**；
- 它**不能**决定谁先饱和——饱和由 `J` 与 `u_max` 决定，而 `u_max` 大的机构（大推进器、主翼面）本来就**最后**才饱和。

因此「让大机构优先饱和」这个目标本身要重新表述。而且在冗余设计上，**让大机构先满等于放弃了冗余**——小型配平面存在的意义就是在大机构用满之后接手余量。真按这个方向调，等于花一套复杂分配器做出一个简单分配器的效果。

**但它在游戏里可以是优点**，所以这条按表现需求定，不按控制理论定：

| 取向 | 表现 |
| --- | --- |
| 大机构优先用满 | 主翼面 / 大喷口先吃满，玩家看得见「它在使劲」；动作可预测、好调试、好做动画 |
| 小机构优先用满 | 大机构留余量给突风、损伤与瞬态修正；动作更细腻但不直观 |

这是**手感旋钮**，不是精度旋钮。

**但这条旋钮有一条物理上正确的取值。** 作动器的代价并不对称：推进器烧燃料、发热、有寿命；气动面不烧任何东西。把这件事编码进 `W` 就得到「推进器贵、气动面便宜」，而它一次性换来一条**跨速度包线**：

| 工况 | 结果 |
| --- | --- |
| 悬停 / 低速 / 地面 | 气动列的模长本来就趋零，只有推进器可解——**纯推力混合器**。这不是规则，是列的性质 |
| 高速 | 气动面优先干活，推进器留余量给突风、损伤与瞬态修正 |
| 中间 | 两者按列范数连续过渡，没有模式机、没有配平表 |

这一条把第二职责从「纯手感」提升为「有物理依据」，但**取向仍按表现定**：想让玩家看见大喷口在使劲，就把推进器调便宜。

## 6. 被取代的做法：按轴独立钳制

一种不引入任何线性代数的做法是：把每个力源的方向投影到体轴上逐轴求和，得到「各轴可用的力区间」，再把力的包络当成一个 3 维盒、力矩的包络当成另一个 3 维盒，各自独立钳制。写下来是因为它的三处代价**恰好就是本方案要消除的东西**，而且它们生效时都不报错。

**逐轴求和的形式**（本体坐标系）：

```
上限_i = Σ_力源 max(0, 方向_i) × 该力源可用出力
下限_i = Σ_力源 min(0, 方向_i) × 该力源可用出力
```

这两个量是**带符号的力**，不是出力的幅度；`方向_i` 是该力源推力方向在体轴 `i` 上的分量，取正取负由安装朝向决定。公式里只有 `max` 与 `min`，没有取绝对值、也没有下限截断，因此 `上限_i ≥ 0`、`下限_i ≤ 0` 由构造保证：

| 该轴上装了什么 | 方向分量符号 | 可用区间 | 说明 |
| --- | --- | --- | --- |
| 正反向各一组 | 两种符号都有 | `[−a, +b]`，`a, b > 0` | 双向下限非零，**这是唯一有意的非零下限情形** |
| 只有正向 | 全为正 | `[0, +b]` | 下限为零 |
| 只有反向 | 全为负 | `[−a, 0]` | 上限为零 |
| 没装 | 无项 | `[0, 0]` | 上限下限同时为零 |

**下限为零的含义是「该轴没有反向驱动能力」，不是「出力关不掉」。** 区间以零为一个端点，恰好说明零出力永远可达（不点火）；推力不可反向的推进器**不会**表现为非零下限，它只往一侧贡献，另一侧的界就是 0。这条语义在分配器里以「`u = 0` 永远在界内、且 `w_alloc = 0 ⟹ u = 0`」的形式保留（§2.2、§7）。

**三处代价：**

| # | 代价 | 为什么 |
| --- | --- | --- |
| 1 | **力的方向自由** | 按轴分解之后，单个机构的实际力矢量允许与安装方向或可达曲线不同。舵面比推进器严重——它的可达集是一维曲线，连盒的角点都不可达。模型因此「比真实机构更能干」 |
| 2 | **形状近似** | 逐轴求和与真实可达集的形状无关。**斜装是触发点**：一台方向为 `(0.3, 0, 0.95)` 的推进器会把上下界同时抬高一截，而它的真实贡献只是一条一维线段；逐轴求和把它铺成了二维或三维区域。最坏情况的系统性高估是体对角上的 `√3 ≈ 1.73`。纯正交安装（`±X` / `±Y` / `±Z` 各就各位）时两条代价都不产生误差 |
| 3 | **力与力矩的耦合不建模** | 同一次分配同时决定 `ΣF` 与 `Σ(r×F)`，两者可能冲突，而独立钳制会悄悄牺牲其中一方，**没有任何地方报告这个冲突**。若力矩由引擎从作用点导出，`Σ(r×F)` 的相消关系会自动成立；本方案手工算力矩，所以相消必须显式保留 |

**为什么最终不采用它**：这三处代价都不是数值误差，而是**模型与真实能力不一致**，并且都在静默生效——高估只表现为收敛比模型预测的慢，冲突只表现为某个轴悄悄不到位。修掉它们必须在 wrench 空间里描述可达集，那正是 §4 的那张 `J`。而「各作动器的方向、满出力、最大偏角、力函数」这些数据在两种做法里都要准备，**引入分配器只多一个 6×6 求解器，却省掉整套逐轴盒的合成、合并与钳制规则**。此外它还省掉一步：这条路分配出来的是**逐轴力**，每个作动器的偏角要从力反解，而且同轴多面之间有剩余自由度、得再定一条分担规则；分配器直接输出 `u`（§4 附带收益二）。

**相关的一条做法：按主/副输出给气动面分类。** 给每个气动面标一个类型，让它的「副输出」（控制面的阻力增量、减速板的力臂力矩）换一条通道走前馈，主输出进控制力。它在动力学上不重不漏（`F` 与 `τ` 出自同一个 `δ`，分开送进两条通道后相加仍等于真实值），代价是**配装期负担 + 配错即静默失效**：把控制面配成减速板，它的力矩会被前馈预先抵消掉，副翼推不动飞机，而且不报错。分配器里没有「主输出/副输出」这个概念——一片舵面的力与力矩由同一个 `u` 一起产出，不存在「哪一半算控制力」，因此那个配置字段与配套的配装期校验都不需要。

## 7. 混合作动器与代回复核

**单侧与双侧的界混在同一个 `u` 向量里。** 归一化之后推进器是 `[0, 1]`、舵面是 `[−1, +1]`（§2.2）。级联钉界时必须**记住钉的是哪一个界**，§5.1 第 ⑤ 步的乘子符号检查要按作动器类型取符号。这不是新算法，是记账。

**一条免费的不变量**：`w_alloc = 0 ⟹ u = 0`。因为 `u = 0` 在界内，且 `W` 正定，阻尼最小二乘的最小努力解就是零。这是「零出力永远可达」在分配层的形态，也是最值得写成单测的一条：**任何配装下，零指令都不许点火。**

**分配输出是「期望的可命令量」，不是「已实现的」。** §2.3 给作动器属性列了响应时间，速率限制会让实际值落后于指令，因此实际气动力/推力不等于 `J u`。代回复核必须走完整条链：

```
u_cmd → 作动器响应模型 → u_actual → 该作动器自己的力函数 → 实际 wrench
```

**代回复核是纪律，不是优化。** 跳过它就成了「先假设这个力可达、再按假设施加」——那不再是模型误差，而是**凭空造力**。它与 §2.1 的目标减法互补：减法保证「要的那份」进得了饱和判断，复核保证「给的那份」真的出得来。

**二值作动器（固体火箭、姿控喷口一类，`u ∈ {0, 1}`）当前不纳入。** 它们的可行集非凸，连续最小二乘会给出「50% 油门」这种不存在的中庸解，而且不报错。登记为 §10.2 的待定项；接入前必须先决定是 PWM 成一阶等效、还是像接触型一样留在分配器之外。

## 8. 分配问题的维度

**分配问题的行 = 引擎实际接受的 wrench 分量。** 引擎不接受的分量不该进目标。把它们留在问题里会让分配器把作动器权限花在无效方向上，而且残差会报出一个**并不存在的饱和缺口**——残差是 windup 保护的输入（§5.1），这个谎会被用上。角色控制器侧哪些分量不被接受、由什么门控，见 `docs/角色控制器-刚体动力学方案.md` §8.3、§9.4。

**行集合由调用方给出。** 分配器只收一个行掩码（或等价地，一张「力 3 行 + 若干力矩行」的表），它不知道掩码是怎么来的：

```
活行 = { 力 x, 力 y, 力 z } ∪ { 力矩 i | 掩码_i ≠ 0 }
```

**降维与「乘一个 0 掩码」逐位等价。** 零行在 `JᵀJ`、`Jᵀw_alloc` 里贡献恒为零；在 `J W⁻¹ Jᵀ + λ²I` 里它只留下一个 `λ²` 对角元，而对应右端项为 0，于是那一行的解分量 `y_i = 0`；再经 `u = W⁻¹Jᵀy` 乘回时又遇到零列。所以两者给出**相同的 `u`、相同的越界列、相同的残差**。既然如此就取更省的那个：直接砍掉行，Cholesky 从 6×6 降到 4×4（角色控制器的地面站立 / 行走与落地收敛窗口就是这一档，见 `docs/角色控制器-刚体动力学方案.md` §9.4），而且**不存在「行掩码与实际维度走样」这种失效**。

**降维不是「忽略」那些力矩，而是「不再试图满足」它们。** 被释放的作动器权限自动转到还活着的行上：一台装在质心上方的推进器在地面只贡献力行，不再被分一份去顶根本不生效的 pitch 力矩。这不需要任何额外规则。

**地面 yaw 行的权限范围要写清。** 它只覆盖作动器能提供的那部分（偏心力源的力臂力矩）。机娘的转向能力还来自**落脚点选择**，而接触型在分配器之外（§1），所以**分配器不管走路转向**。

**切换瞬间的指令阶跃**，两个方向不对称：

| 方向 | 后果 | 由什么吸收 |
| --- | --- | --- |
| **收行**（6 → 4） | 需求本来就在趋零 | 角色控制器的落地摆正已经把 pitch / roll 的力矩需求往零收敛，**「先摆正、后降维」是自然顺序，不需要额外过渡逻辑**（`docs/角色控制器-刚体动力学方案.md` §5.1、§5.3） |
| **放行**（4 → 6） | 两行突然出现，分配器第一次能命令 pitch / roll 力矩 | 由调用方的飞行控制层吸收：PD 属它，角加速度必须限幅（`docs/角色控制器-刚体原型与引擎约束.md` §7.2）。**但控制层必须知道当前行表**，否则它在什么维度上工作都是猜的 |

**死行上出现非零分量有两种来源，处置完全不同**：

| 来源 | 例子 | 处置 |
| --- | --- | --- |
| `w_des` 在死行上非零 | 地面上控制层还在要 pitch 力矩 | **上层搞错了**，应当断言或记日志 |
| `w_known` 在死行上非零 | 地面上一片机翼的升力在质心上方产生 pitch 力矩 | **正常，静默丢弃**——引擎也会吃掉那份力矩，所以它既进不了刚体、也不需要被抵消 |

## 9. 跨线程与跨端

**`u` 要跨线程、也大概率要跨端。** 分配器在**物理线程**上跑，而程序性动画（§4 附带收益二）在客户端渲染侧。通路：

```
物理线程：解出 u  →  不可变快照  →  主线程  →  同步给客户端  →  动画消费
```

三件事要一起定：

1. **不要跨线程直接读写。** 沿用既有的不可变快照形态（`common/control/MechaControl.java#LogicStateSnapshot` 就是物理线程 → 主线程的出口），不要给 `u` 另开一条可变引用。
2. **同步频率不必跟物理步。** 动画要的是平滑过渡，不是 100 Hz 的原始序列：可以按较低频率发 `u` 并在客户端插值，也可以只发已经归一化的「油门」与「偏角」两组量。
3. **它要么进 `SynchedEntityData`，要么进新的载荷字段。** 按仓库的字段表纪律，`EntityDataAccessor` 只能在末尾追加，且改动字段表或载荷字段后必须同时提升 `network/ARMSNetwork.java#PROTOCOL_VERSION`。

## 10. 待定项

### 10.1 权重矩阵 `W` 的取向

**第一职责要定的只有一个基准，第二职责要定一个取向。**

| 层 | 要定什么 | 现状 |
| --- | --- | --- |
| **量纲归一化**（必须） | 把力（N）与力矩（N·m）拉到可比尺度的基准：按质量与惯量、按权限上限、还是按误差容限 | 只差一个实测系数：机娘 yaw 惯量按当前几何约 4.4 kg·m²，**尚未在真实配装下量过**；归一化必须让这一行的权重与三个力行可比 |
| **优先顺序**（按表现定） | 冗余时谁多干一点——大机构先满（直观、好调试）还是小机构先满（大机构留余量给瞬态与损伤） | 有一条有物理依据的候选取值：「推进器贵、气动面便宜」（§5.2），它一次性换来跨速度包线；是否采用仍是表现选择 |

**为什么第二职责不现在定**：优先顺序依赖调用方的控制层——那里才给出 `w_des` 各分量的相对重要性；归一化基准则要等承载物的力学质量与惯量定下来，并在真实配装上量一次转动惯量。

**定了之后动什么**：`W` 的第二职责对角系数、§5 里 `λ` 的归一化前提、§5.2 的两层职责、以及 §10.2 的系数。

### 10.2 分配器的数值细节

**已经定了的**：

| 项 | 结论 | 出处 |
| --- | --- | --- |
| 饱和处理 | **级联**：一次全取、一起钉，不追 KKT 最优。每轮至少钉一列且永不释放，因此最多 `N` 轮 | §5.1 |
| 要不要收尾乘子检查 | **可选**。零迭代增量（残差是求解副产品，检查只要一次 `N×k` 乘），加上它就把残差明确做成「饱和缺口」输出 | §5.1 |
| 残差怎么用 | 直接作为饱和缺口喂给 windup 保护，不另设饱和判据。**缺口是相对于 `w_alloc` 算的**，因此配平需求不算缺口 | §5.1 |
| 正则化 | **必须**，取 `λ² = ρ · mean(diag(JW⁻¹Jᵀ))`，`ρ` 从 `1e-4` 起调。它让矩阵恒为正定，同时消灭「约化系统减秩」这条失效 | §5 |
| 单侧与双侧界混合 | 记账问题：钉界要记类型，乘子符号按类型取 | §7 |
| 线性化可信域 | **关闭**。用界上的割线，两端严格精确；区间内偏差实测峰值 7.5% 列模长，由闭环吸收 | §3.1、§3.2 |
| 要不要引入线性代数库 | **不引入**。只需 6×6 或更小的对称正定 Cholesky，约 40 行，且它是纯函数、可完整单测 | §5 |
| 门控与降维的关系 | 行表由调用方给出的掩码直接导出，不设独立门控矩阵——两者逐位等价，而前者不可能走样 | §8 |

**仍未定的三件**：

1. **失速边界上列的抖动**：列模长在攻角越过失速角之后掉得很快，且伴随方向变化，不是「跳到零」。低通、平滑裁剪、或接受，需要一次实测看它在边界附近抖得多厉害。力函数的真实形态见 `docs/角色控制器-刚体动力学方案.md` §10.1、§10.3。
2. **遮挡复用的乘性误差是否可接受**：求导时复用 `u = 0` 那一次算出的遮挡因子，而射线方向随偏角转（遮挡半径默认 1.0 m、`δ_max` = 25° 时端点横移约 0.42 m）。需要确认机娘的部件间距是否落在会让它出错的量级；该默认半径是按载具尺度给的，见 `docs/角色控制器-刚体动力学方案.md` §12.6。
3. **作动器响应模型的形态**：代回复核链（§7）中间那一步取什么——纯速率限、一阶滞后、还是直接用上一拍的实际值。时钟错拍那一份是**已知量**（`docs/角色控制器-刚体动力学方案.md` §10.2：本步气动用的是上一步末的关节角），待定的只是伺服在一步内能走多远。它决定复核的严格程度，也决定 §2.3 的「响应时间」属性怎么落地。

**需要谁定**：前两件要实测数据；第三件与调用方的飞行控制层一起定。
