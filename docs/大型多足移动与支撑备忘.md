# 大型多足移动与支撑备忘

> **状态**：设计备忘，未实施，无当前开发排期。
> **记录日期**：2026-11-14。
> **适用对象**：大蜘蛛、机械蟹、三脚或多脚机甲等宽跨度素体。
> **目的**：记录中央移动代理、足部 IK、跨沟支撑和地形姿态的组合思路。算法与参数均为候选，尚无本项目实测结论。

## 1. 基本取舍

多足的足部跨度可以大于身高，也可以远大于躯干半径；这个比例本身不决定是否能够使用角色控制器。

优先考虑以下组合：

- 中央圆柱作为整体移动代理，半径按躯干占据的空间确定。
- 各腿有独立的落脚点、支撑期 / 摆动期和 IK。
- 有效支撑脚决定身体的目标高度、俯仰和侧倾，并限制整体移动。
- 正常支撑时，身体刚体通过根约束追踪目标位姿。
- 支撑持续失效时，撤去虚拟支撑，按失衡策略释放身体根约束。

这条路线使用简化的整机支撑判据，不要求先实现逐关节力矩控制或逐腿承重求解。完整动力学步行属于另一种精度选择，适用于关节受力、打滑和失衡过程本身构成玩法的场景。

## 2. 移动代理与实际身体

圆柱可以保持竖直，实际躯干具有独立的俯仰与侧倾目标。圆柱负责整体移动和碰撞，躯干及肢体的实际碰撞体负责对应部位与环境的接触。

| 几何量 | 用途 |
|---|---|
| 躯干占据的空间 | 圆柱半径及身体碰撞轮廓 |
| 各腿能够到达的范围 | 落脚点搜索、跨沟能力和步幅 |
| 当前支撑脚的位置 | 支撑稳定性、目标高度及倾角 |

跨沟本身不强制缩短圆柱。高圆柱也可以由远处的脚提供虚拟支撑，但它会阻挡腹下的一部分空间。若要求车辆、岩石能够处于腹下，应让碰撞轮廓贴近躯干，并将站姿高度与碰撞体半高分别定义。

腿部碰撞可能挡住某条腿，而中央圆柱仍有移动空间。落脚点可达性和腿部阻挡应当能够限制推进，避免根约束持续牵引被环境卡住的肢体。

## 3. 有效支撑脚与稳定性

有效支撑脚需要同时满足：腿具有支撑能力、处于支撑期、落点存在可接受的支撑面、落点在当前身体位姿下可达。摆动脚和只有 IK 目标却没有落脚面的脚不计入承重判据。

静态地形上的支撑落点固定在世界坐标中；若支持移动平台，则保存相对平台的落点并随平台变换。不能让支撑点每步随身体平移后向下探测，否则会把脚的滑动误当作持续支撑。

第一版可采用重力方向上的准静态近似：将有效支撑接触投影到水平面，构建凸包，检查整机质心沿重力方向的投影是否位于其中。质心可先按躯干中心近似，质量分布明显偏置时需要修正。

- 判定对象通常是质心投影，要求支撑多边形覆盖整个圆柱底面属于额外的保守规则。
- 使用到边界的距离作为稳定余量，避免恰好位于边缘时反复切换。
- 接触不足三个非共线点时，点接触凸包没有面积，不能按正常稳定区域处理；有限足底面积可作为后续扩展。
- 对短暂欠稳定设置容忍时间，允许换步和补步。所有脚均失去落脚面时撤去支撑，避免无支撑悬停。
- 此判据用于缓慢行走的近似，不保证快速运动、强碰撞、陡坡或攀壁时的动力学稳定。

## 4. 身体悬在沟上

### 4.1 支撑来源

身体下方没有地面，但两岸的有效支撑脚能够托住身体时，中央代理应保持站姿高度。沟底深度不参与这份支撑高度计算。

需要区分“圆柱与地面有接触”和“足部存在有效支撑”。仅将着地布尔设为真，不能托住一个没有底部接触的动态刚体。

### 4.2 目标高度与可达性

对于给定的身体水平位置和旋转（含倾角），每条支撑腿给出近似可达的身体高度区间 H_i。可用高度范围为这些区间的交集：

```text
H_available = intersection(H_i)
y_target = clamp(y_preferred, H_available)
```

该区间应考虑腿长、关节范围、髋部位置及水平伸展距离，不能只按脚底高度加固定腿长估算。交集为空时，应尝试换步、调整姿态或停止推进；身体不能靠 IK 超伸维持移动。

| 情形 | 预期行为 |
|---|---|
| 两岸同高，脚可达，质心受到支撑 | 身体保持适当高度，允许位于沟上 |
| 身体前进使某条支撑腿接近伸展极限 | 安排换步；找不到可用落点时限制推进 |
| 两岸有高差 | 联合调整身体高度和倾角，并复核各腿可达性 |
| 沟宽超过可达范围 | 停止正常跨越；按行为选择退回、跳跃或失衡 |

### 4.3 虚拟支撑与水平驱动

候选实现是在有效支撑期间，对中央动态刚体施加一份有上限的竖直支撑力：

```text
F_y = clamp(m*g + k_p*(y_target - y) - k_d*v_y, 0, F_max)
```

m 为该移动代理的动力学质量（kg），g 为重力加速度的大小（m/s²），y_target 与 y 分别为目标高度和当前高度（m），v_y 为当前竖直速度（m/s）。k_p 和 k_d 分别为高度恢复系数（N/m）与速度阻尼系数（N·s/m），F_max 为支撑力上限（N）。该式针对世界 Y 轴竖直的场景；支撑能力、质量口径和响应参数需要标定。运动学锚点承担身体约束反作用时，不能假定各身体刚体的负载已经传到代理上。

第一版可以只求一份整机支撑力，由支撑判据决定其有效性。圆柱实接触与足部虚拟支撑交接时，需要协调承重份额，避免两条通道重复提供完整支撑。

水平驱动同样需要接受足部支撑结果：沟上没有圆柱底面的接触摩擦，驱动预算与驻停不能依赖这份接触。可先在有效支撑时以约 m*g 的载荷估算牵引上限，并提供主动制动 / 驻停。中央圆柱的接触冲量不能冒充足部实测承重。

## 5. 身体随各足高度调整姿态

### 5.1 支撑参考平面

用支撑脚的实际落点拟合参考平面。世界 Y 轴竖直时，可使用加权高度拟合：

```text
minimize sum(w_i * (a*x_i + b*z_i + c - y_i)^2)
plane: y = a*x + b*z + c
up_target = normalize(-a, 1, -b)
```

其中 (x_i, y_i, z_i) 为第 i 个落点的世界坐标，w_i 为非负拟合权重，表达接触可信度和姿态过渡的影响程度，不代表实测承重。

支撑脚通常不共面，拟合给出整体地形趋势。脚底局部法线不能代替落点高度关系：两个高度不同的水平平台，其接触法线都可以竖直。

前高后低产生抬头目标，左高右低产生侧倾目标，两岸同高时跨沟不应因沟底深而低头。身体朝向由移动 / 朝向意图决定，俯仰和侧倾由参考平面提供。

### 5.2 跟随程度与平滑

身体姿态是对参考平面的可配置跟随，不要求与其完全平行：

- 设置地形跟随权重，在保持水平与跟随地形之间选择倾向。
- 限制正常行走的最大倾角及转动速度。
- 支撑脚进出集合时渐变拟合权重，配合目标高度和姿态的时间平滑，抑制换步抖动。
- 摆动脚不充当实际支撑。足部接触可靠性与姿态插值权重是两种量，姿态插值的残留权重不能延长已经失效的物理支撑。
- 对单脚踩小石块等离群高差限制影响；拟合退化时可短时保持目标或趋向水平，但持续失去支撑仍须进入下落 / 失衡处理。

### 5.3 高度、倾角与稳定性联合检查

倾斜会改变各腿髋部的位置和质心投影，因此不能把高度区间与倾角完全独立求解。候选简化顺序为：拟合目标倾角 → 限幅和平滑 → 按该姿态求可达高度 → 复核各腿与质心 → 必要时减小倾角、调整高度或请求换步。

参考平面决定期望姿态，支撑凸包决定准静态支撑是否成立。三只位于身体同一侧的脚能够拟合平面，也可能无法托住身体。倾斜后的身体还必须满足自身碰撞空间要求。

## 6. 失衡与身体权威

正常支撑 → 欠稳定并尝试补步 → 超时失衡 → 释放身体根约束，是候选状态流程。完全离地需要撤去虚拟支撑并保留实际运动，不应由欠稳定容忍计时维持悬停。

释放约束只保证身体能够自由运动。具有实际足地接触的肢体可能产生自然翻倒；只有 IK 表现的腿不能提供这种接触力矩，身体可能直接下落。需要指定倾倒方向时，可添加有界的倾倒动作或角冲量。

失衡期间，位置与姿态的输出应由实际身体提供，宿主、同步和渲染应读取对应权威。继续用中央代理驱动锚点或回写身体，会抵消失衡。肢体关节的动画驱动强度也需要按失衡状态处理。

失衡应具备独立于死亡的语义；起身、重新捕获根约束和恢复移动的条件留待具体玩法设计。

## 7. 代码接入坐标与待确认项

以下是记录时可定位的实现事实，以及候选接入位置；不表示多足能力已经存在。

| 坐标 | 实现事实 / 候选接入点 |
|---|---|
| `src/main/java/io/github/sweetzonzi/arms_core/common/control/MechaCharacter.java#MechaCharacter` | 移动代理继承动态刚体，实际碰撞与积分由物理引擎处理 |
| `src/main/java/io/github/sweetzonzi/arms_core/common/control/MechaCharacter.java#updateGround` | 中央碰撞体向下扫掠给出着地结果；足部支撑需要独立表达并参与运动判断 |
| `src/main/java/io/github/sweetzonzi/arms_core/common/control/MechaCharacter.java#planDrive` | 驱动预算消费支撑载荷；虚拟支撑应定义自己的载荷来源与驻停语义 |
| `src/main/java/io/github/sweetzonzi/arms_core/common/ArmsCoreServerEvents.java#collectSupportImpulses` | 收集中央控制器的支撑冲量，不能据此推断远处足部承重 |
| `src/main/java/io/github/sweetzonzi/arms_core/common/control/MechaCharacter.java#settleUpright` | 控制圆柱的直立姿态；实际躯干的地形倾角可以由独立锚点目标承担 |
| `src/main/java/io/github/sweetzonzi/arms_core/common/part/ArmsBodyPhysics.java#rootJoint` | 身体根部与运动学锚点的六自由度锁定约束，失衡释放的候选位置 |
| `src/main/java/io/github/sweetzonzi/arms_core/common/part/ArmsBodyPhysics.java#bodyTarget` | 身体目标由控制器位姿和固定竖直高差构成；多足目标高度与姿态的候选接入点 |
| `src/main/java/io/github/sweetzonzi/arms_core/common/part/ArmsBodyPhysics.java#followControllerStep` | 跟随目标并提供位置 / 偏航补偿；支持躯干倾角时需评估完整角速度目标 |
| `src/main/java/io/github/sweetzonzi/arms_core/common/ArmsCore.java#prePhysicsTick` | 控制器推进后更新身体锚点，足部采样、姿态规划和关节 IK 的物理步顺序需明确 |

开始实施时需要确定：素体几何与髋部定义、步态和补步规则、有效支撑的坡度范围、虚拟支撑容量与质量口径、身体碰撞和腿部阻挡、运动平台、失衡 / 起身流程，以及权威状态同步。圆柱半径与高度也需要按素体配置。

验证场景至少包含：同高两岸跨沟、两岸高差、单脚踩石块、换步过程中接触集合变化、落脚点超出腿长、全部离地、腿被墙卡住，以及失衡释放后身体不会被代理拉回。
