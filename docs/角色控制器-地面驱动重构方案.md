# 角色控制器：地面驱动重构方案

> 状态：驱动数学、水平执行链、Post 载荷缓存与低速制动辅助已实现，见 §7、§8.3、§11、§13.3。逐 Part 属性来源、完整坡面映射及动态支撑反馈待实施；属性类型为 `common/control/attr/LegDriveAttr.java#LegDriveAttr`。
> 日期：2026-11-14。§2.2 的隔离测量基线为 `05c6a7bc`；实施落点使用可检索的活引用。
> 目标：以少量零件属性表达推进、超速反拖、降档减速和松键制动，保留动力学响应，并解决落地瞬间水平速度被大量消耗的问题。

源码短路径 `common/…` 以本仓库 `src/main/java/io/github/sweetzonzi/arms_core/` 为前缀。公式中的力用 N、速度用 m/s、功率用 W、时间用 s；角速度用 rad/s。

## 1. 范围、决策程度与相邻文档

### 1.1 已形成的设计方向

1. 角色由动态刚体接受力、冲量和接触求解；速度由物理积分产生。
2. 地面运动采用整机等效驱动，不模拟左右脚的摆动相位、落脚规划或交替承重。迈步由表现层动画表达。
3. 驱动能力属于 Part 的属性。控制器收集有效 Part，逐件求出有符号贡献再合成；腿力本身不建立独立子系统。
4. 最大力与工作速度定义力速能力，功率由曲线导出。内容包无需再为同一能力填写一个必须兑现的峰值功率。
5. 允许慢速源在超速时反拖，因此快慢零件混装的结果由各源的推进与制动共同决定。
6. 行走、慢跑、冲刺具有不同工作速度与功率能力；冲刺切回慢走需要主动减速。正常受控状态下，松开方向键意味着停住并站稳。
7. 基础地面切向作用只有一份预算：推进、反拖、制动与侧向控制不能分别使用一整份附着额度。低速制动辅助在基础裁剪后混合，可超过基础预算，见 §7.5。无移动输入且相对运动足够小时交给求解器摩擦保持，判定由速度门与有效控制输入组合得到；保持与主动制动的设计边界见 §7.3。
8. 推进器使用 Machine-Max 的控制分配路径；出力响应后的实际力、力矩参与物理，腿力与推进器可以同时作用。

### 2.2 隔离测量揭示的两个问题

2026-11-12 在裸 PhysicsSpace 上做了持续前进与落地对照，步长为 0.01 s，Libbulletjme 为 23.1.2；测量使用正式控制器但不包含身体装配与 Minecraft 地形接触回调。复现场景见 §14。

**持续前进测试需要同时记录支撑和位置。** `src/test/java/io/github/sweetzonzi/arms_core/common/control/RigidBodyControllerMeasurementTest.java#flatRig` 的地面沿前进方向延伸至 50 m，`src/test/java/io/github/sweetzonzi/arms_core/common/control/RigidBodyControllerMeasurementTest.java#measureSteadyStateSpeed` 统计 12 s 末段速率，但没有断言采样期间始终着地或已经收敛。

| 场景 | 12 s 速度 | 30 s 速度 | 60 s 速度 |
| --- | ---: | ---: | ---: |
| 地面半长 50 m，倍率 1.0 | 24.7645；已离地 | 78.7645；已离地 | 168.7645；已离地 |
| 地面半长 5000 m，倍率 1.0 | 10.7058；着地 | 13.3433；着地 | 16.5776；着地 |
| 地面半长 5000 m，倍率 0.3 | 8.4548；着地 | 11.1855；着地 | 14.4295；着地 |
| 地面半长 5000 m，倍率 0 | 1.1948；着地 | 2.9607；着地 | 5.9035；着地 |

在 50 m 地面、倍率 1.0 的场景中，首次失去支撑约为 6.98 s，位置约为 z=50.69 m。因此 24.7645 m/s 不能解释为地面稳态速度。长地面上倍率为零但保持方向输入时出现持续前进，与前馈未被驱动倍率关闭相符。

有效的地面 12 s 读数是倍率 1.0 下的 **10.7058 m/s，且尚在加速**。它与 `docs/角色控制器-刚体动力学方案.md` §12.10 记载的倍率 0.3、有限地面场景中约 10.7 m/s 的输出不是同一次读数，不能据数值相近推断档位或倍率没有作用。该文 §7.4、§11 的 P3 行、§12.10 与 `AGENTS.md` 的速度说明使用相同的场景限定。

**落地存在显著的接触切向速度损失。** 初始脚底高 5 m，水平速度 6 m/s，各场景独立运行：

| 对照 | 首次撞地前水平速度 | 该物理步之后 |
| --- | ---: | ---: |
| 正式控制器，持续前进，角色摩擦 2.0 | 9.10191 | 0.26836 |
| 裸刚体，无主动驱动，角色摩擦 2.0 | 6.00000 | 0.18147 |
| 裸刚体，无主动驱动，角色摩擦 0 | 6.00000 | 6.00000 |

裸刚体对照把主要损失定位到接触摩擦；此结论不代表游戏里所有落地损失都只有一个来源。落地法向冲量较大时，默认切向摩擦可能在同一步消耗大量水平动量。只调整主动推进力，不能证明已经解决这一问题。

## 3. 属性与运行职责

### 3.1 Part 提供能力，控制器拥有运行状态

| 位置 | 内容 |
| --- | --- |
| Part 的静态定义／变体 | 可选的地面驱动属性，供同型号实例共享 |
| Part 实例 | 当前变体、有效性及需要时的损伤修正；暴露当前可用参数 |
| ArmsCore / MechaControl | 收集驱动 Part，选择档位，推进响应，逐件求值并汇总 |
| MechaCharacter / 接触执行层 | 观测支撑，提供当前物理状态，执行统一的切向请求与法向碰撞 |

没有驱动属性的 Part 贡献零腿力。驱动资格按属性和有效装配成员身份判定，不依赖名字里是否含有“腿”。腿力本身没有独立的信号总线、tick、启动顺序或网络状态；需要独立控制的推进器使用自身的作动器接线。

重构目标是由随模组分发的素体 Part 属性提供基础行走能力，默认素体无需额外内容包即可移动；目标控制器不保留内置兜底曲线。现役曲线位于 `common/control/MechaCharacter.java#computeDriveForce`，最大力取 `common/control/attr/MechaWalkingAttr.java#F_MAX` 的 700 N；Part 属性方案尚未实施。目标形态下，缺少驱动属性的自定义装配体没有主动腿力，并给出诊断。内置定义需指定唯一的能力归属，例如每侧小腿各贡献一份，大腿与足部缺省为零；数值随 P4 标定确定。裸圆柱测量通过测试夹具显式注入能力。

装配体允许的成员类型见 `common/ArmsCore.java#acceptsPartType`。BodyPart 与 RegularPart 如何接入同一可选能力，属于属性接口的待定范围；不能只扩展 BodyPart 的 Codec 就宣称所有 Part 类型均已支持。

当前 BodyPart 大腿和小腿是分别定义的 Part，例如 `src/main/resources/spark_modules/arms_core.builtin/arms_core/parts/allbody_thigh.json` 与 `src/main/resources/spark_modules/arms_core.builtin/arms_core/parts/allbody_shin.json`。每项能力表示本 Part 的贡献，不能把一整条腿的完整出力重复填到各段。一个 Part 有多个 SubPart 时，Part 级能力只统计一次。

是否要求完整的髋—腿—足装配链才能启用某项能力，以及损伤衰减采用什么函数，见 §12；本稿不以虚构的左右脚相位解决结构有效性。

### 3.2 物理步数据链

```text
观测支撑与相对运动
  → 采样逻辑输入、确定控制许可与档位
  → 推进控制器的响应状态
  → 遍历有效驱动 Part，各自按当前状态求有符号贡献
  → 汇总请求并施加共享能力／附着约束
  → 按完整相对速率混合低速制动辅助
  → 接触执行与其他力源求值
  → Bullet 步进
  → Post 阶段汇总已求解的有效支撑法向冲量，复制成下一步使用的值
  → 按既有线程协议发布结果
```

支撑查询、刚体读取和施力在物理线程完成。逻辑与驱动消费同一物理步的支撑观测。主线程变更装配或内容定义时，应发布可在物理步边界安全读取的成员与属性视图；不能在物理遍历期间任意改写其集合。

实际出力必须每步按速度求值，不能把某一速度下的出力缓存成固定整机属性。成员数很少时，直接遍历即可；缓存成员列表的必要性由实际装配更新与性能决定。

## 4. 内容包参数的工作基线

每个驱动 Part 使用一个最大力 `F_i`，以及行走、慢跑、冲刺三个空载工作速度 `V_{i,g}`。空载速度是该源在该档位的零出力点，不是整机速度硬上限。

| 参数 | 单位与含义 |
| --- | --- |
| 最大力 `F_i` | N；该 Part 对整机的低速有效推进能力，不是某个真实脚接触点的瞬时峰值；整机合计后仍受 §7.1 的附着上限约束 |
| 三档速度 `V_{i,g}` | m/s；行走／慢跑／冲刺的零出力速度 |
| 反拖能力 | 可选参数或共用默认规则；限制负半段，见 §5.2 |
| 制动辅助 `brake_assist` | 无量纲 [0,1]，默认 0；在低速区混入标准指数制动的比例，范围取该 Part 的慢跑速度，见 §7.5 |

逻辑档位对应当前 `common/control/state/domain/Gait.java#CREEP`、`common/control/state/domain/Gait.java#JOG`、`common/control/state/domain/Gait.java#SPRINT`。字段命名、JSON 所在层级及变体继承尚未定稿。以下只表达数据内容，不是已发布的 Codec：

```json
{
  "ground_drive": {
    "max_force": 300.0,
    "brake_assist": 0.5,
    "no_load_speeds": {
      "creep": 2.0,
      "jog": 6.0,
      "sprint": 10.0
    }
  }
}
```

配置校验需要拒绝非有限值、负能力、非正的有效工作速度及超出 [0,1] 的辅助比例。`common/control/attr/LegDriveAttr.java#LegDriveAttr` 的六参数构造器接受辅助值，五参数构造器取 0；上面的 JSON 仍是数据形态示例。没有能力可用时以属性缺省或明确停用表达，不能把空载速度填成零后参与除法。普通三档建议满足 `V_creep ≤ V_jog ≤ V_sprint`；是否作为发布时的硬校验，见 §12。

“一速＋共用三档倍率”可以成为一力三速的简写，但会固定所有腿的档位速度比例。是否提供这种简写、是否允许逐变体覆盖，须随内容定义格式确定，不能由运行时静默猜测。

## 5. 有符号力速曲线与合成

### 5.1 同向一维的数学基线

令 `u` 为移动意图在支撑切平面的单位方向，`s = dot(v_t,u)` 为带符号沿向速度。逐源、逐档求值必须先处理逆向速度，再限幅，最后才能参与求和及权重混合：

```text
s_eff      = max(s, 0)
raw_f_i,g  = F_i · [1 − (s_eff / V_i,g)²]
f_i,g      = clamp(raw_f_i,g, −B_i, +F_i)
```

以下用 `v = s_eff ≥ 0` 比较曲线形状：`v < V_i,g` 时贡献推进，`v = V_i,g` 时贡献零，`v > V_i,g` 时进入反拖。`s < 0` 时沿意图给出最多 `F_i` 的正向力，先消除逆向运动，再继续推进。平方放在归一化速度上；`(1 − v/V)²` 会让接近零出力点的推进能力弱于线性曲线，不表达本稿选择的中高速出力形状。

| v / V | 线性 1−v/V | 平方 1−(v/V)² |
| --- | ---: | ---: |
| 0 | 1 | 1 |
| 0.5 | 0.5 | 0.75 |
| 0.8 | 0.2 | 0.36 |
| 0.95 | 0.05 | 0.0975 |
| 1 | 0 | 0 |

有限力引起有限加速度，不能把当前速度直接设置为 `V_i,g`。连续时间下接近零点的收敛可以是渐近的；是否达到稳态需按加速度和速度窗口判定。离散步进必须覆盖穿越零点、反拖和参数极值的稳定性，不能用很大的曲线指数代替响应标定。

正向限幅与 `s_eff` 在 §5.3、§6 的合成之前执行。仅写 `min(raw_f,F_i)` 不能等价代替 `max(s,0)`：平方曲线在 `s=−V` 时原始值为零，在更大的逆向速率下甚至给出错误的负向力。水平侧向速度和二维预算见 §7.4，不能把世界水平速率代替带符号投影。

### 5.2 负半段有界

平方曲线的原始负值随速度增大，实际反拖必须限幅。工作写法可以表示为：

```text
−B_i ≤ f_i,g ≤ F_i                    // 在 §5.1 中逐源完成
```

`B_i` 是该 Part 的反拖力上限。反拖倍率、吸收功率上限是否独立配置、默认能否自由随动，均为 §12 的参数项；原始负值不能未经限幅进入刚体。

反拖表示当前驱动源在耦合状态下吸收机械能。它不是“只要着地就固定向后扣除 μmg”。选择自由随动的源可以把超速贡献截成零；选择反拖的源在超速时保留有限负贡献。本文的快慢腿混装基线允许后一种行为。

### 5.3 先逐件求值，再求和

```text
F_legs,g(s) = Σ_i f_i,g(s)                    // 单档，i 为有效驱动 Part
F_legs(s)   = Σ_g w_g · F_legs,g(s)           // 实际档位混合，权重由 §6 给出
```

单档示例取该档权重为 1；响应过渡期按第二式合成。这与 §7.1 的 `q_i,g = w_g·f_i,g` 使用同一权重，不能将两式先后重复加权。

例：两个源的最大力分别为 600 N、300 N，当前档位空载速度分别为 6 m/s、12 m/s，采用平方曲线。若反拖限幅尚未触发，在 v=√48≈6.928 m/s 时，两个贡献分别为 −200 N、+200 N，合力为零。该数值是假设没有其他切向力的模型平衡点，不是游戏内标定结果。

慢速源可以拖慢高速源，整机也无需套用“取最慢腿速度”的规则。不能先算平均速度再配合总力求值，因为那通常不等价于逐件相加。逐源反拖限幅、损伤修正等也必须在它们实际定义的层级执行。

接触执行层对合成需求使用共享的二维附着预算。这个整机抽象不求解每只脚的接地载荷；它的代价是不能预测单脚打滑、步态失衡和非对称落脚。

### 5.4 功率是导出量

推进区间内：

```text
P_i,g(v) = v · f_i,g(v)
P_i,g,peak = 2 / (3√3) · F_i · V_i,g ≈ 0.385 · F_i · V_i,g
```

一个 600 N 的源，三档速度取 2、6、10 m/s 时，曲线峰值功率约为 462、1386、2309 W。因此共享最大力并不意味着三档功率相同；冲刺能在高速保持出力，对应的峰值机械功率高。

各源的峰值可能发生在不同速度。整机峰值要逐速求值和合成后寻找，不能把各源峰值功率之和直接当成同时可用的整机峰值。

存在正负贡献时，推进功率和吸收功率分别记录；合力为零不代表没有能量流。这些是简化模型的机械功率，不能直接充当持续体力／能源消耗。平地匀速时人体依然存在摆腿与步间转换等功耗，相关区别见[关节机械功与代谢研究](https://pubmed.ncbi.nlm.nih.gov/21613286/)及[步间转换研究](https://pubmed.ncbi.nlm.nih.gov/15821430/)。游戏能源结算需要独立的简化损耗规则，不在腿的 F/V 属性中强加第三个独立功率参数。

## 6. 档位与出力响应

同一最大力下，各档的零速出力能力相同；行走曲线在低速结束推进，冲刺曲线在高速持续推进。若直接使用整条曲线作为实际请求，各档刚起步时可能有相同加速度。慢走柔和、冲刺迅速发力的差别，交给控制器的出力建立过程表达。

一阶响应采用按步长计算的精确离散系数：

```text
α = 1 − exp(−dt / τ)         τ = 0 时直接取 α = 1
```

一个候选是维护档位权重 `w_g`，在目标档位 h 有效时：

```text
w_g ← (1 − α)·w_g + α·[g=h]
F_legs(v) = Σ_i Σ_g w_g · f_i,g(v)
```

初始推进权重可以为零，从静止逐渐建立出力；中途切档从当时权重继续过渡。每步各曲线都用当前速度求值，避免把过时的实际推力当作速度反馈。权重为非负、总和不超过 1；硬件有效性与接触资格在本步重新检查。

混合期的零合力速度通常不等于任何一档的 `V`。在同向且所有限幅均未触发的区间，令 `A = Σ_i,g w_g F_i`、`D = Σ_i,g w_g F_i/V_i,g²`，则零点为 `sqrt(A/D)`（`D>0`）；有限反拖或外部阻力介入后按实际合力求根。这是曲线混合的预期结果，P4 报告须注明档位权重，不能把过渡期零点变化当作标定漂移。

| 过程 | 响应要求 |
| --- | --- |
| 建立行走推进 | 较长的建立时间，起步平滑 |
| 建立慢跑推进 | 中等建立时间 |
| 建立冲刺推进 | 很短或零建立时间；瞬时的是力的建立，速度按动力学改变 |
| 降档与松键制动 | 使用制动响应规则，不能因行走的建立时间较长而长期保留正向推进 |

时间常数的具体数值、降档是否直接切入目标曲线或使用短过渡、停车对权重的处理，均须测量。此处的权重是现有逻辑档位的响应状态，不是左右脚的物理步态。

档位权重只作用于沿向力速请求。§7.4 的侧向制动按本步速度与附着预算直接求值；重力、碰撞反力、外部冲击和推进器自身响应不经过档位低通。失去支撑、Part 失效等硬条件立即使相应能力失效。

## 7. 无输入：有限制动与站稳

### 7.1 三类请求及唯一的基础预算

正常受控状态下，无方向输入意味着停车，不使用 `V=0` 代入力速曲线。基础制动能力 `B_legs = Σ_i F_i`，不提供独立最大制动力配置；低速响应由 §7.5 的辅助比例表达，失能许可见 §12。

先按 §5、§6 求出每项带权贡献 `q_i,g = w_g f_i,g`，分别记账：

```text
F_drive = Σ max(q_i,g, 0)         // 推进请求，非负
F_regen = Σ min(q_i,g, 0)         // 超速反拖请求，非正；名称不承诺能源回收

有输入：F_request = F_drive + F_regen
无输入：F_request = F_brake       // 整体替代推进与反拖
F_execute = clamp(F_request, −J_max/dt, +J_max/dt)
```

这是一维合成顺序。§7.4 的二维实现将未做整机裁剪的沿向请求与侧向请求组成一个矢量，再投影到同一允许域；各轴不能独占一份整机预算。`F_i`、`B_i`、`B_legs` 分别是正向、反拖、主动停车的能力边界，`J_max` 是合成后本步执行的冲量边界，不能都称为同一种“最大能力”。

**附着是基础分支的硬上限。** 无论 `F_i`、`B_i`、`B_legs` 取多大，基础分支的冲量都不超过 `μ_pair_base·N_eff·dt`。裁剪作用在**合成后的整机基础请求**上一次（`F_execute`），不逐 Part、也不逐接触点各扣一次，否则 `n` 个接触点会得到 `n` 份额度。主动阶段原生摩擦为 0（§8.1），求解器不会替这次裁剪兜底。§7.5 的辅助在裁剪后混合制动分量，最终制动力允许超过此上限；沿向推进／反拖仍使用基础结果。引擎的组合摩擦只有一个系数，静摩擦与动摩擦同值，没有另一档动摩擦可用。

### 7.2 运动中的主动制动

对静态平地的质心近似，基础请求为：

```text
F_brake = −normalize(v_t) · min(B_legs, m_eff·|v_t|/dt)
J_max   = min(F_cap·dt, J_adhesion_est)
```

`F_cap` 根据当前请求选择推进／反拖／停车能力，`J_adhesion_est` 是 §8.3 的附着估计。公式没有把静态 `m·g·cosθ` 叫作本步真实法向冲量。动态甲板上的 `m_eff` 还含支撑质量、两侧转动项与作用点；P0 可先用刚体质量近似，但必须量出误差。

动量限幅可避免单独的制动力把速度推过零；重力、其他力源和耦合接触仍会改变该步结果，不能据此保证所有场景绝无过零。高速度时采用有限制动，低速可按 §7.5 混合辅助，近零时进入 §7.3 的接触保持。辅助为 0 时，100 kg 机体、600 N 可用制动力、从 6 m/s 停下，在附着充足且没有其他力时约需 1 s。

### 7.3 近静止保持：速度门与有效控制输入

Bullet 的接触摩擦会在求解过程中按需要抵抗切向运动，适合处理近零速的小扰动。保持是否启用由每步的输入与相对速度直接推导，不建立独立的 HOLD 状态机、驻留计时或落地计时。

以下适用于正常受控且有有效支撑的机体。`hasMoveInput` 表示经过死区与控制许可处理后的有效移动请求，不直接等同于某个键是否按下；`v_t`、`v_n` 是相对支撑的切向和法向速度，取法见 §9。

```text
holdGate = groundControlEnabled && validSupport
           && !hasMoveInput
           && |v_t| < v_hold
           && |v_n| < v_normal_hold

有有效移动输入：普通腿力请求，受控点组合滑动摩擦系数为 0
无输入且 !holdGate：基础制动及可选低速辅助，受控点组合滑动摩擦系数为 0
holdGate：主动切向请求为 0，启用该接触对的基准组合摩擦
```

DRIVE、BRAKE、HOLD 在本文只作为这三个派生分支的简称。每物理步在控制阶段计算并冻结保持许可，使主动请求与接触写入使用同一份结果；输入生效当步释放保持。因此静止起步不会被摩擦锁住，无输入的高速滑行先由腿力刹停；明显的法向接近速度使落地冲击不能进入保持。

Pre／Processed 接触回调仅负责执行系数写入，不推进逻辑状态机、响应权重或计时。回调可用本点即时速度和接触资格否决保持，不能把控制阶段未允许的保持临时打开；若因这项保护留出一拍未制动，接受这一误差，下一物理步重算请求。新接触静置时可以直接保持，不因“首触”本身强制建立一个历史状态。无 Post 样本也不妨碍从材质现算基准组合摩擦；Post 缓存只参与载荷与可选限幅。

速度阈值由 P0 标定。首轮采用直接速度门；若实际观测到门附近频繁切换，再评估很小的进入／退出速度差，不预设多段过渡。跳跃、支撑失效与控制许可变化使对应保持许可立即失效。输入被禁用是否代表主动停车，由 §12 的状态许可另定。

**`v_hold` 是交接冲量的尺度。** 门打开的当步，剩余相对速度由求解器在一步内抹掉，冲量约为 `m·|v_t|`，等效力 `m·|v_t|/dt` 可以远大于 `B_legs`。阈值因此不只由「站稳」决定，还受交接冲击约束：

```text
v_hold ≤ min( B_legs·dt/m , μ_pair_base·g·dt )
```

第二项是一步内原生摩擦最多能抹掉的相对速度（`μ·J_n = μ_pair_base·m·g·dt`），第一项使交接力不超过主动制动力。70 kg、600 N、`μ_pair_base`=1.0、100 Hz 时两项分别为 0.0857 与 0.0981 m/s，取小者约 0.086 m/s，因此 `v_hold` 落在 0.05–0.09 m/s 区间自洽；取值更大即等于瞬时制动。门以下的相对速度交给摩擦，门以上的追平由主动制动承担，两者不靠放大门限互换。

**保持预算必须明示。** 原生摩擦上限为本步 `μ_pair_write·J_n`，不是 `B_legs·dt`。主原型将 HOLD 视为被动接触保持，腿能力约束主动阶段；静止抗推能力可能大于腿的主动制动力。若站稳也需受腿能力限制，比较 §8.2 的缓存缩放保持，接受一步估计误差；严格上限需要相应约束接口。P0 记录持续外力、低附着斜坡及门限切换的表现，不能据求解器保持就宣称所有场景绝无振荡。

### 7.4 水平侧向：摩擦量级制动与共享预算

有输入时，将相对支撑的水平速度投影到输入单位方向 `u=(dirX,dirZ)` 与正交侧向基 `r=(−dirZ,dirX)`。沿向继续求逐 Part 力速曲线；基础侧向使用与摩擦同量级的显式制动，不单独配置侧向力速曲线或时间常数：

```text
s = dot(v_relative_horizontal, u)
q = dot(v_relative_horizontal, r)
f_along_request = Σ_g w_g · Σ_i f_i,g(s)
f_side_request  = −sign(q) · min(μ_pair_base·N_eff, m·|q|/dt)

F_limit = min(Σ_i F_i, J_adhesion_est/dt)
L = hypot(f_along_request, f_side_request)
scale = L > 0 ? min(1, F_limit/L) : 0
(f_along, f_side) = scale · (f_along_request, f_side_request)
F_horizontal = f_along·u + f_side·r
```

侧向取零时返回零力。动量项使该制动力单独作用时最多消除本步已有侧速，共享裁剪的缩放系数不大于 1，因此基础分支不会自行过零。外力与支撑运动造成的过零另计。低附着使收侧速变慢；沿向推进／反拖与侧向制动同时请求时，基础分支按合成向量方向统一缩小。该分支共用 `Σ F_i` 的整机力圆上限，辅助按 §7.5 在其后混合。

无移动输入时不建立输入侧向基，直接沿完整相对速度反向使用 §7.2 的停车制动。保持门继续检查完整相对速率，不能只因侧速接近零就开启原生摩擦并刹住前进。

数学入口为 `util/control/GroundDrive.java#evaluate`，其计划同时返回沿向与侧向分量；单轴入口以侧速为零调用二维求值。`common/control/MechaCharacter.java#planDrive` 在输入基中投影相对水平速度，`common/control/MechaCharacter.java#updateWalk` 将计划的两个分量合成世界 XZ 力后施加。两者的水平基旋转只计一次。当前实现延续控制器的水平平面与甲板速度观测，完整坡面切平面及动态支撑反馈按 §12 评审。

### 7.5 低速制动辅助：一个比例、固定慢跑参考

每个驱动 Part 提供 `a_i = brake_assist ∈ [0,1]`。0 表示只用 §7.2、§7.4 的基础模型；1 表示低速区采用标准指数响应；中间值是混合比例，不是力倍率。辅助范围固定使用该 Part 的 `V_i,JOG`，不受当前档位和 §6 的权重影响，不增加辅助速度或响应时间配置。

令 `s = |v_relative_horizontal|` 为完整相对水平速率。逐 Part 的速度包络、整机混合权重为：

```text
h_i(s) = exp(−(s / V_i,JOG)^4)
a_eff  = Σ_i [F_i · a_i · h_i(s)] / Σ_i F_i   // 无能力时取 0
```

最大力为 0 的装饰源不会稀释辅助。同一零件在慢走、慢跑、冲刺时使用相同包络；切档不会改变辅助参考。以 4 m/s 慢跑参考为例，2、4、6 m/s 的包络分别约为 0.9394、0.3679、0.00633。侧向辅助也按完整速率衰减，避免高速前进时只有少量侧速却触发强低速辅助。

受控制速度 `v_c`：无输入时取完整相对水平速度；有输入时只取侧向分量 `q·r`。先求基础裁剪结果中的相应制动分量 `F_base,c`，再混合：

```text
λ_standard = −ln(0.546) / 0.05 s ≈ 12.102726 s⁻¹
α          = 1 − exp(−λ_standard · μ_pair_base · dt)
F_exp,c    = −m · α/dt · v_c
F_final,c  = (1−a_eff) · F_base,c + a_eff · F_exp,c
```

标准响应在组合摩擦为 1、低速包络趋近 1 时，每 50 ms 保留 0.546 的受控制速度，作为接近原版草地减速节奏的内部标定。摩擦影响指数衰减速率：无摩擦时没有辅助，低附着时减速较慢。辅助不是额外叠加一份最大力，也不在混合后按 `μN` 或 `ΣF_i` 再裁剪；它允许最终制动力超过基础能力，以提供明确的低速操纵响应。

两个分支均耗散且按本步已有动量有界，凸组合不能仅靠自身把受控制速度推过零。指数分支在极低速时可能小于基础定力制动，因此辅助值增大不保证每个速度点都产生更大力；近零站稳按 §7.3 的速度门处理。有输入时沿向推进／超速反拖完整保留基础结果，辅助只混合侧向制动。这里不提供沿向加速伺服，也不进入空中控制或修改 QB／闪避的速度赋值规则。

实现位于 `util/control/GroundDrive.java#brakeAssistWeight`、同文件 `#assistBrake`。`common/ArmsCore.java#DRIVE_ATTRS` 的内置双腿显式取 1；五参数 `common/control/attr/LegDriveAttr.java#LegDriveAttr` 的默认值为 0。

## 8. 接触执行、摩擦与落地

### 8.1 普通施力作为优先路线

脚在蹬地时的静摩擦可以提供动力；随圆柱整体平移的底面则会被默认模型视为滑动面。腿力模型与圆柱接触之间需要处理这项表达差异，但不要求把所有驱动都改写成接触目标速度。

主原型采用普通力：整机求基础结果、混合辅助后施加一次最终力；角色侧以质心中心力施加，动态支撑侧应在支撑作用点施加其相反数，辅助也计入反作用。动态支撑反馈尚待 §12 的质量／作用点接线，不能从水平执行链推断其已完成。主路线没有摩擦前馈。HOLD 的原生摩擦反作用由求解器处理，应用层不得另加一份。

**主动阶段的组合系数明确取零。** DRIVE/BRAKE 在求解前将有效支撑点的 `m_combinedFriction` 写成 0。保持门通过时，写回完整的接触对基准值 `μ_pair_base`。主路线没有摩擦补偿，600 N 腿力即使小于平地的 `μ_pair_base·mg=686.7 N`，也没有额外的原生滑动摩擦来抵消起步。

**材质值与组合值分别定义。** `μ_self`、`μ_other` 是双方原始材质／配置值；`μ_pair_base` 是按接触对和材质规则得到的完整组合值，`μ_pair_write` 是本步实际写给求解器的值：

```text
默认各向同性组合：μ_pair_base = μ_self · μ_other
受控支撑点写入：  μ_pair_write = holdGate ? μ_pair_base : 0
主动附着预算：    J_adhesion_est = μ_pair_base · N_eff · dt
```

例如双方为 2.0 与 0.5，保持时写回 1.0。地形材质与湿滑修正可参考 `../Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/collision/CollisionHandler.java#setupContactFriction` 的按点组合写法，双方材质变化时刷新基准。优先从原始材质现算，不能将已被本控制器覆盖成 0 的接触值反读作材质；若缓存原始 `m_combinedFriction`，须在控制器覆盖前采集完整值，绑定接触生命周期并随材质变化刷新。不能只存角色侧系数，也不能照搬 MM 的 0.001 下限到主动分支，主动分支必须允许真零。

Bullet 的组合生成与使用分别见 `../Libbulletjme/src/main/native/bullet3/BulletCollision/CollisionDispatch/btManifoldResult.cpp#addContactPoint`、`../Libbulletjme/src/main/native/bullet3/BulletDynamics/ConstraintSolver/btSequentialImpulseConstraintSolver.cpp#setupFrictionConstraint`。写入接口为 `../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/physics/body/ManifoldPoint.kt#setCombinedFriction`。

**当前版本没有切向冲量的跨步 warm start。** `../Libbulletjme/src/main/native/bullet3/BulletDynamics/ConstraintSolver/btSequentialImpulseConstraintSolver.cpp#setupFrictionConstraint` 每步把摩擦约束的 `m_appliedImpulse` 置零；同文件 `#setFrictionConstraintImpulse` 也是清零入口。求解后的 `m_appliedImpulseLateral1/2` 会写回 manifold 供观测，但该求解器没有读取它们播种下一步摩擦约束。主动阶段不需要清这两项来抑制历史摩擦。法向 warm start 是另一件事，此处不修改它。

摩擦方向与初始化标志具有持久字段，规则见同文件 `#convertContact`。`../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/physics/level/PhysicsWorld.kt#PhysicsWorld` 的模式含 CacheDirection，但没有 Use2Directions 与 NoVelocityDependent；在没有外部手动设置方向初始化标志的角色接触上，求解器每步按相对速度生成方向，极低速时使用切平面基。自动置初始化标志需要双摩擦方向与禁用速度相关方向同时开启，不能把当前配置下的方向字段持久化说成摩擦冲量 warm start。手动标志与目标运动的候选见 §8.2。

基础分支的冲量为 `J_base = F_execute·dt`，`|J_base|≤min(F_cap·dt,J_adhesion_est)`。启用 §7.5 时，实际主动冲量按混合后的力计算，制动分量可超过基础上限；两份结果分别记账。法向碰撞照常求解；侧墙、顶棚与非支撑接触不参与保持门写入。滚动／自旋摩擦另行声明和记录。碰撞结果不得被速度回写覆盖。

**按回调职责写点。** 新点在 `../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/physics/level/PhysicsWorld.kt#onContactConceived` 派发的 Collide.Pre 中处理，持久点在同文件 `#onContactProcessed` 派发的 Collide.Processed 中按本步门值刷新。生产调用 `../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/physics/level/PhysicsLevel.kt#runStepRound` 的布尔参数为 `false,true,false,true`；`../Spark-Core/src/main/java/com/jme3/bullet/PhysicsSpace.java#update` 的签名依次是 doEnded、doProcessed、doStarted、doPreAdd，故 Processed 与 conceived 均开启。P0 验证两个入口都确实写到最终求解值，尤其是静置同一接触点上反复改变输入；不将 Processed 是否开启列为未知前提。两侧处理器可能先后写同一点，需核对最后写入者，控制器只覆盖自己的有效支撑摩擦。

**行为边界。** 主动阶段的低附着通过软件预算裁剪，表现为起步慢、制动距离长、转向可能横漂；没有独立脚或轮面的滑移率。圆柱在行走时本就相对地面平移，不能把其接触切向速度直接标成脚底打滑；表现层如需信号，可报告请求超出附着额度的比例，但名称与含义应为预算饱和程度。DRIVE/BRAKE 的转向、坡向控制和移动甲板跟随由主动请求及相对速度承担，支撑接触没有额外切向拖带；HOLD 时才由原生摩擦提供被动保持。 保持门只看相对速度的大小，不区分相对速度由哪一侧造成：平台起步把角色的 `|v_t|` 推出门时，角色按主动制动追平；平台急停产生同一个量时，角色同样按主动制动停下，摩擦在两者中都不参与。急停情形里原生摩擦本可在一步内拽住，这是规则的对称结果而不是遗漏；两种情形都记录追平行程与时间。追平时长受附着预算限制而不只受腿力限制：`μ_pair_base`=0.1 的甲板上 `J_adhesion` 每步只有 0.687 N·s，约合 68.7 N，追平 5 m/s 需约 5.1 s、相对滑移约 12.8 m。

**守恒范围只主张主动反作用对的线动量。** 令 `F_applied` 为含辅助的最终施力；角色质心 `c` 与支撑作用点 `p` 不同，力对每步引入未平衡角冲量 `ΔL_pair=(c−p)×F_applied·dt`。这是等效腿力省略角色侧接触力矩的代价；角因子锁转与绝对朝向写入还提供外部角约束，所以控制器与甲板不是角动量封闭系统。不能把这份差额全部说成“已经传给角色但被角因子过滤”：中心力本身就没有角色侧力矩。P0 分别输出 `ΔL_pair`、锁转轴、两侧实际角动量变化与朝向写入的差额。300 N 水平力、竖直力臂 1.2 m 对应 360 N·m，100 Hz 下为 3.6 N·m·s 的量级。

这条路线的基础分支由控制器估计附着限制，而非让求解器逐点精确限制人工中心力；辅助按 §7.5 定义，多接触和甲板加速误差单独记录。它足以成为 P0 主方案，`contactMotion` 没有必要作为实施前提。

### 8.2 三类接口对照及退路

| 候选 | 能表达什么 | 限制与测量项 |
| --- | --- | --- |
| 普通施力＋输入速度门 | 非保持分支一份整机有限力、无前馈；保持分支使用基准组合摩擦 | 主路线。Pre 覆盖新点、Processed 刷新持久点；附着限制由 §8.3 的有限力估计承担 |
| 按上一步法向冲量缩放保持摩擦 | 保持门通过时的可选对照，将原生保持预算近似限制到指定能力 | 仅在 HOLD 且有有效缓存时，若 `μ_pair_base·N_raw>0`，取 `r=clamp(min(F_limit,μ_pair_base·N_eff)/(μ_pair_base·N_raw),0,1)`，完整组合系数取 `μ_pair_base·r`；`N_raw/N_eff` 见 §8.3。无缓存时不使用比例式，基线保持门通过则写基准组合值；门不通过则取 0。禁止将重力兜底代入比例式，不能保证本步硬上限 |
| contactMotion 目标速度 | 通过摩擦约束趋向目标相对速度 | 没有独立的腿力上限；仍受当前 `μ·J_n` 限制，存在方向缓存与多点耦合 |

第二项是有稳定缓存的 HOLD 实验。单独测试角色侧 `setFriction` 时，该 setter 只写刚体属性，不能据此假定所有持久接触点的组合摩擦立即更新。接触系数在接触点生成／替换路径中计算，见 `../Libbulletjme/src/main/native/bullet3/BulletCollision/CollisionDispatch/btCollisionObject.h#setFriction`、`../Libbulletjme/src/main/native/bullet3/BulletCollision/CollisionDispatch/btManifoldResult.cpp#addContactPoint`。整刚体系数还会影响侧墙，因此只用它作成本对照，主路线仍按点筛选与写入。

contactMotion 只作可选对照。`../Libbulletjme/src/main/native/bullet3/BulletDynamics/ConstraintSolver/btSequentialImpulseConstraintSolver.cpp#convertContact` 在开启方向缓存且置有 `BT_CONTACT_FLAG_LATERAL_FRICTION_INITIALIZED` 时才使用 `m_contactMotion1/2`；当前生产模式不会自动给普通角色接触置该标志，候选必须手动接线。单独的切向约束若希望产生带符号冲量 `J_desired`，目标近似为 `v* = v_t + J_desired/m_eff`；若 `J_desired` 专指正的制动冲量大小，则沿滑动轴写 `v* = v_t − J_desired/m_eff`。`m_eff` 含两侧转动项，质量近似需报告误差；重力、外力、其他约束及多点耦合使这只是一种映射，不能保证实际冲量恰等于请求。

接口为 `../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/physics/body/ManifoldPoint.kt#setContactMotion1`、同文件 `#setContactMotion2`、`#setFlags`、`#setLateralFrictionDir1`。置位后不能假定摩擦基随速度更新。候选做法是在求解前每步重写合法切向基、目标和初始化标志，并验证双方向配置；仅清标志可能使当步走入忽略目标速度的自动方向分支。P0 量方向误差及一步滞后，不能凭接口名称判通过。

普通施力的可行性前提是 §8.1 的系数写入真正覆盖求解前路径。若该前提没有满足，P0 先查漏掉的新点／持久点、被覆盖的组合系数和方向／初始化标志；不能靠加前馈掩盖它。接口无法兑现零摩擦主动阶段时，评估专门的有限力切向约束。完整材质摩擦加前馈属于另一种施力契约：它需要分别核算补偿、实际接触摩擦和平台反作用，不能与本文的主路线共用“直接施力上限”验收。

### 8.3 Post 汇总：载荷估计与多接触

**在 postPhysicsTick 收集求解后冲量、缓存到下一步是可行的。** 对每个有效支撑组复制法向、法向冲量、支撑体标识、接触位置和步长，不跨步持有原生点 id。只统计符合承重法线与有效接触条件的点；侧墙、顶棚、非承重碰撞与重复枚举不能加进腿的载荷。不同法线的点先投影到选定支撑法线，明显不相容的支撑不能直接合成一个标量。

```text
J_n,prev = Σ 有效支撑点的已求解法向冲量（按支撑法线投影）
N_prev   = J_n,prev / dt_prev          // N，上一物理步的平均反力
N_static = m·g·cosθ                    // N，当前生产实现的静态近似
N_raw    = 有有效缓存时取 N_prev，否则取 N_static
N_eff    = 对 N_raw 进行下述软压缩
J_adhesion_est = μ_pair_base · N_eff · dt_current
```

**重力兜底只进入这份力／冲量预算。** 它不是用来计算落地步的非零 Bullet 摩擦系数。静态平地、70 kg、`μ_pair_base=1`、100 Hz 时，重力给出的附着预算为 6.867 N·s，最多对应 0.0981 m/s 的速度变化；若制动能力仅 300 N，则实际预算为 3 N·s，对应约 0.04286 m/s。把 300/686.7 写成系数会使求解器乘上另一份真实落地法向冲量，已经是不同模型，不能称为重力力预算。

**大载荷采用按重力归一化的软压缩。** 这里表达腿能用于蹬地／制动的等效载荷，不改写真实碰撞冲量。令 `N_g = m·g·cosθ`，以两个无量纲整机参数 `κ>0`、`a>0` 定义：

```text
x = N_raw / N_g
h(x) = x                                      x ≤ κ
h(x) = κ + a·ln(1 + (x−κ)/a)                   x > κ
N_eff = N_g · h(x)
```

低载荷区域取真值；阈值处函数值和一阶斜率连续；高载荷下单调增长，增长率逐渐趋零。首轮标定可取 `κ=2`、`a=1`：1、2、10、90 倍静态载荷分别映射到 1、2、4.197、6.489 倍。这是对数压缩而非有限值的硬饱和，主动腿力另受自身上限限制。参数先归控制器共用，内容包作者无需逐腿填写。

不同支撑组先在同一整机支撑参考下聚合法向载荷并压缩，再按原始有效载荷比例分配 `N_eff`；不能每个接触点各享一次 `κ·N_g` 的真值区。各组材质不同则用 `Σ_j μ_j·N_eff,j·dt` 合成附着额度。重力为零时本公式没有归一化基准，需显式选用绝对载荷尺度或关闭该压缩，不能用除零结果驱动。`J_n/dt` 中冲击峰值受步长影响，P0 比较生产 100 Hz 与其他步长的结果。

这是一种游戏中的腿缓冲等效：它限制可利用的切向附着，不模拟屈膝行程，也不能延长真实法向碰撞的持续时间。基准保持门由输入与速度决定，不依赖 Post 样本；可选的软压缩保持需有效缓存，按 `N_eff/N_raw` 缩放完整组合值并接受一步误差，不能称其为本步精确上限。明显落地冲击因法向速度门失败而不启用保持。

时序依据：`../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/physics/level/PhysicsLevel.kt#physicsTick` 是求解后的 Post；`../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/physics/level/PhysicsWorld.kt#onContactProcessed` 是碰撞回调。Bullet 的 `../Libbulletjme/src/main/native/bullet3/BulletDynamics/Dynamics/btDiscreteDynamicsWorld.cpp#internalSingleStepSimulation` 先碰撞检测，再解约束，最后调用 Post。因此 **Collide.Processed 不是本步求解完成事件**，其中读到的冲量不能标作当步最终法向冲量。

**相位可读性的实测读数。** 70 kg 圆柱从高出地面 2 cm 处落下并静置，100 Hz，逐步读同一接触点的法向冲量（`src/test/java/io/github/sweetzonzi/arms_core/common/control/GroundDriveRefactorMeasurementTest.java#measureSupportImpulsePhases`）：窄相里读到的和恒等于上一步求解的和（0 → 4.2071 → 43.8619 → 6.8670 N·s，逐点相等，误差小于 2e-3 N·s），静置后两侧都等于 `m·g·dt = 6.8670 N·s`，落地步的求解值是静置值的 6.39 倍，新接触点在窄相里读到 0。三条结论：写摩擦的那一刻本步的法向冲量不存在；缓存不是额外存一份量，而是把同一个量推到下一步使用；落地峰值使未经压缩的缓存不能直接当预算——6.39 倍静态载荷经本节软压缩（κ=2、a=1）映射到 3.68 倍，附着预算从 43.86 N·s 降到 25.30 N·s。

MM 的先例是 `../Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/common/mech/ObjectManager.java#onPostPhysicsTick` 调用 `../Machine-Max/src/main/java/io/github/sweetzonzi/machine_max/common/mech/vehicle/collision/CollisionPostSettlement.java#settle`，后者扫描 manifold 并在同文件 `#collectManifold` 读最终冲量。该实现筛选 SubPart—地形伤害候选，角色控制器和甲板支撑需要自己的筛选／聚合，不能把伤害折算值直接当承重冲量。

首版接受一步估计误差：有效 Post 样本经软压缩后供下一步使用，没有样本则按重力估算，不建立冲击载荷预测器。缓存只用一物理步，失联立即失效。即使压缩后的附着估计变大，基础主动冲量也始终受 `F_cap·dt` 限制；§7.5 的制动辅助独立混合，不由落地冲量放大。保持门只用控制输入与相对速度，和载荷估计分开；无样本不构成等待保持的理由。快速升降／加速甲板的误差在 P0 记录，无需为消除一步延迟增加求解前多接触预测。

**实现状态与读数。** 缓存是 `src/main/java/io/github/sweetzonzi/arms_core/util/control/SupportLoadCache.java#SupportLoadCache`：样本只用一步、零冲量等于没有样本（接触断开即自然过期）、载荷按样本自己那一步的步长除出。写入点是 `common/ArmsCoreServerEvents.java#onPostPhysicsTick`，读取点在 `common/control/MechaCharacter.java#planDrive`——先取 `N_raw`，再经上面的软压缩得 `N_eff`，最后进 §7.1 的一次裁剪。落地场景的读数（`src/test/java/io/github/sweetzonzi/arms_core/common/control/GroundDriveRefactorMeasurementTest.java#measureSupportLoadCacheThroughController`，70 kg 圆柱从 2 cm 落下、固定双腿夹具、100 Hz）：

| 步 | 本步求解出的 J | 本步用的 `N_eff`（来自上一步的 J） | 说明 |
| ---: | ---: | ---: | --- |
| 0–4 | 0.0000 N·s | 686.7 N | 尚未真正承重，没有样本，取 `m·g` |
| 5 | 4.2071 N·s | 686.7 N | 首个承重步：本步仍要用静态兜底 |
| 6 | 43.8619 N·s | 420.7 N | 用的是 4.2071 N·s，即 0.61 倍静态载荷，低于 κ 因而原值进入预算 |
| 7 | 6.8670 N·s | 2529.8 N | 用的是 43.8619 N·s：6.39 倍经软压缩成 3.68 倍 |
| 8 起 | 6.8670 N·s | 686.7 N | 静置，缓存与静态估算重合 |

第 6 行是这套缓存唯一会「低于静态值」的场合：承重首步的接触还不完整，冲量只有 0.61 倍静态载荷，而 `κ=2` 之内取真值，于是下一步的附着预算比站立时低。它只影响一步（10 ms），若 P0 的落地读数表明这一拍影响手感，可选处理是给 `N_raw` 加一个不低于 `N_g` 的下限，而不是改压缩曲线。

普通施力路线只有一份主动预算，**不需要在求解前猜每个接触点本步分到多少法向冲量**。多个支撑体的反作用按上一步各组有效法向冲量比例分配；新组没有历史时在有效组间均分。相反，若候选按点设置目标或摩擦预算，则同一组内按上一物理步的点冲量比例分摊，首帧／点匹配失败时均分，所有点份额总和等于该组预算。这些都是因果估计，需量接触重排误差。

### 8.4 首个落地步与恢复

带输入、明显切向运动或明显法向接近速度都会使保持门失败，受控支撑点的组合摩擦系数明确为 **0**。典型高速落地首步因此没有原生滑动摩擦刹车；基础主动预算缺样本时使用 `N_static`。若启用 §7.5，另按本步速度和基准摩擦计算辅助，不能把真实落地法向冲量乘入辅助。新点与持久点都执行同一规则，不能仅因切向速度接近零就启用保持。法向冲击保持原样。

无输入且两项相对速度都足够小的静置接触可启用基准组合摩擦，不要求首触后再等固定步数。后续 Post 缓存只更新主动载荷预算或可选缩放保持；有缓存不自动打开保持门。落地速度损失判据对主动分支与被动保持分别记账，门限内的残余速度消除也须记录。Post 缓存不能撤销已发生的首步损失，起落速度在窄相确认时按即时速度安全门处理。

若原型需要落地能力恢复，采用 `F_contact=r_contact·F_cap`，`0≤r_contact≤1`，在给定 `τ_land` 内单调恢复到 1；它不能超过腿能力，也不能把首步偶然的低冲量永久缓存成刹车上限。是否需要该平滑由测量决定，默认不额外衰减能力。作为量级参照，100 Hz 下 3 N·s 等于 300 N；70 kg 机体从 9 m/s 刹停约需 2.1 s。这种滑行可以是有限腿力的正确结果，验收应对照能力，而非要求无输入落地即停。

不能通过每步恢复世界 XZ 速度来验收：那会覆盖外部冲量与平台响应。地形拼缝修正属于法线问题，相关判据见 `common/control/TerrainSeamContactCorrection.java#correctNormal`、`docs/角色控制器-刚体原型与引擎约束.md` §11.10、§11.11。

## 9. 支撑参考系、有效性与时序

设支撑点为 p，角色／支撑体质心为 c_c、c_s：

```text
v_c(p) = v_c + ω_c × (p − c_c)
v_s(p) = v_s + ω_s × (p − c_s)
v_rel  = v_c(p) − v_s(p)
v_t    = v_rel − dot(v_rel,n)·n
```

n 是由支撑体指向角色的单位法线。接触点分离不可忽略时，两侧应分别使用各自的世界接触位置。运动学平台的规定运动也必须进入点速度，不能统一按零速支撑处理。

地面力速查询、转向和制动使用这一参考系；世界速度用于实际积分和同步。触地状态的短暂宽限可用于逻辑表现，但不能凭历史支撑向已失联的平台继续施力。候选扫掠、有效承重与逻辑宽限的区分见 `docs/角色控制器-载具支撑接入计划.md` §4–§6。

主线程不持有接触点原生 id。需要跨步保存的信息复制成值，并在使用时复核对象有效性。warp、支撑离开空间、装配失效和维度卸载需要使相关观测失效；身体与控制器的 warp 接线见 `common/ArmsCore.java#warpController`。

## 10. 推进器、空气阻力与能量

推进器按分配指令、响应模型和器件力函数给出实际出力；以控制器质心为统一参考点归约：

```text
F_thruster = Σ F_i
τ_thruster = Σ [(p_i − c) × F_i + τ_direct,i]
```

不能用分配器的目标 wrench 冒充实际出力；能力不足和响应滞后需要保留在结果中。具体契约见 `../Machine-Max/docs/plan/进行中/控制分配-作动器wrench分配设计.md` §2.1、§7。地面腿力若已经以接触冲量执行，归约记账时也不能重复施加。

空气阻力按相对空气速度、形状和气动参数产生，简单各向同性说明式为 `F_air = −0.5·ρ·CdA·|v_air|·v_air`。它不以有无移动输入为开关，地面与空中都可能存在。身体 SubPart 气动和控制器代理气动的归属必须唯一，调查范围见 `docs/角色控制器-刚体动力学方案.md` §10、§12.5–§12.7。

力速曲线的零点代表执行能力边界，空气阻力代表外部负载，Part 的内部损耗代表能源消耗；三者不能为了得到某个目标速度而任意合并成恒定地面阻力。

轮滑具有滚动方向、横向抓地和滑行等特征；水上驱动还涉及支撑、浮力和流体阻力。它们可以复用 Part 属性收集和控制器接口，但不能仅凭调一组双足速度参数就宣称行为已经定义。

**驱动源的当前来源是硬编码常量。** `common/ArmsCore.java#getDrivingAttrs` 返回两条腿各一份 `common/control/attr/LegDriveAttr.java#LegDriveAttr`（正向 350 N、反拖 350 N、空载速度 1.6／4.317／5.612 m/s、制动辅助 1），与零件构成无关，任何装配体都得到同一组数值。玩家装配体因此走 §5–§8 的力律；空驱动源走 §2.1 明示的前馈回退分支。逐 Part 的来源（Part 定义里的可选字段，加按实际零件汇总）尚未落地。合计 700 N 高于平地的附着上限 686.7 N，低速区的推进由 §7.1 的一次裁剪截住；低速制动按 §7.5 混合，允许超过基础预算。

**内置速度对照原版草地。** 以 Minecraft 1.21.1 无速度效果、无其他属性修饰的玩家，在平坦草地持续前进、不跳跃为基准。`net.minecraft.world.entity.player.Player#createAttributes` 给基础移动属性 0.1，`net.minecraft.world.entity.LivingEntity#aiStep` 对水平输入乘 0.98；`net.minecraft.world.level.block.state.BlockBehaviour#Properties` 的默认摩擦为 0.6，草地定义见 `net.minecraft.world.level.block.Blocks#GRASS_BLOCK`。`net.minecraft.world.entity.LivingEntity#travel` 的速度保留率为 `r=0.6×0.91=0.546`；`net.minecraft.world.entity.LivingEntity#getFrictionInfluencedSpeed` 在该地面给出约 0.1 的输入加速度，因此实际位移的稳态速率近似 `20×0.98×0.1/(1−0.546)=4.31718 m/s`。疾跑修饰 `net.minecraft.world.entity.LivingEntity#SPEED_MODIFIER_SPRINTING` 为 +30%，对应约 5.61233 m/s。这里忽略 float 舍入，不把积分后已乘衰减的 `deltaMovement` 当作当 tick 的位移。

内置常速档取 4.317 m/s 对齐普通行走，冲刺档取 5.612 m/s 对齐疾跑；慢走档为 1.6 m/s。辅助参考自动使用 4.317 m/s 的慢跑零载速度，合成规则见 §7.5。该对齐限定平地稳态速率，加速、制动和负载响应仍由本控制器力学决定。12 s 正式控制器标定见 §13.3。

**Post 接线选择 Level 事件，已经落地。** 事件定义在 `../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/event/PhysicsLevelTickEvent.kt#Post`，发出位置为 `../Spark-Core/src/main/kotlin/cn/solarmoon/spark_core/physics/level/PhysicsLevel.kt#physicsTick`。`common/ArmsCoreServerEvents.java#onPostPhysicsTick` 每步调一次 `common/ArmsCoreServerEvents.java#collectSupportImpulses`：先从注册表列出本 Level 有控制器刚体且已入世的实例，再扫该物理空间的 manifold 一次，按 `common/control/MechaCharacter.java#SUPPORT_NORMAL_Y` 同一道法线门求和，把结果交给 `common/control/MechaCharacter.java#recordSupportImpulse`。未注册／已注销／尚未入世／客户端空壳跳过，因此不在每个 `MechaCharacter` 上重复挂 body Post。一个 Level 一个物理空间，一次扫描覆盖它下面的全部控制器，不每个刚体扫一遍。步长沿用本步的 `1 / PhysicsLevel#getTps()`，不混用游戏 tick 时长。Post 只复制观测数据，下一 Pre 消费；主线程与跨步缓存都不持有原生接触点 id。

当前控制器质量来自 `common/control/attr/MechaWalkingAttr.java#MASS`，身体质量统计位于 `common/ArmsCore.java#getTotalMass`，身体根约束的另一端是运动学锚点，见 `common/part/ArmsBodyPhysics.java#ArmsBodyPhysics`。三者没有自动组成一个双向受力系统。实施前必须明确腿力作用的物理质量、身体质量如何分摊，以及身体受到的外力是否／如何进入控制器；直接把控制器质量与所有身体质量相加不能证明模型正确。

P0 的首轮验收边界如下；这些是原型目标，并非已测通过：

1. DRIVE/BRAKE 的基础冲量 `J_base=F_execute·dt` 不超过 `F_cap·dt`，另受本模型的 `Σ_j μ_pair_base,j·N_eff,j·dt` 限制。辅助为 0 时实际施加值就是基础值；启用辅助时，按 §7.5 核对基础、指数及混合结果，允许制动超过基础力圆／附着，但受控制分量的制动冲量不得超过其已有动量，也不得自行反向加速。沿向推进／反拖不得被辅助修改，无额外摩擦前馈。受控支撑点的原生滑动摩擦冲量应为零；单独量出回调写入残差，不能把残差当作腿力。报告原始载荷、压缩载荷及与本步真实法向冲量的差；HOLD 被动保持按第 3 项另验。
2. 平地落地对照逐步核算切向动量：保持门未通过的物理步，受控支撑产生的损失不超过本步声明的实际制动／反拖冲量除以质量，加 0.02 m/s 的首轮数值容差（100 Hz）；开启辅助时，声明值包含 §7.5 混合后的制动，不能套用未辅助的基础上限。主动分支完整窗口对累计额度核算，额外损失容差 0.05 m/s。门通过后的残余速度消除按被动保持单独记账，并量出门限所允许的损失。保持法向碰撞、控制输入和其他已知切向力的记账，禁止速度回写。若出现 §2.2 的约 9→0.27 m/s 且无法由实际请求解释的损失，则该路线不通过。
3. HOLD 与人工制动互斥，输入生效当步可起步；报告近零反复过零、坡面漂移、持续外力下的抗推上限及冲击期间的状态。被动 HOLD 超出腿能力必须作为明确的模型选项记录。
4. 多接触增减不产生额外整机预算；动态支撑两侧主动冲量相反，仅主张该主动反作用对的线动量守恒。按 §8.1 输出 `ΔL_pair`、锁转轴、两侧实际角动量变化与朝向写入差额，不宣称总角动量守恒。主方案甲板应收到含辅助的 `−F_applied`，不叠加前馈或复制原生 HOLD 摩擦反作用；反馈接线完成后验证。质量／转动近似误差、摩擦写入延迟和方向缓存误差分别输出。

专用约束退路需兑现相同的有限主动作用与落地损失契约，不能因实现简单而放宽损失或宣称低附着由本步精确约束。若需调整容差，必须给出数值噪声基线及其量级依据。

读数的一处前提：该用例把三轴转动全锁。圆柱与盒是单点接触，留 yaw 自由时摩擦约束解的是接触点相对速度，机体先绕 Y 转起来（100 步后 yaw −175.6°），切向冲量只到 5.7581 N·s，机体以 0.39 m/s 蠕行。生产控制器每物理步绝对写入 yaw（`common/control/MechaCharacter.java#writeFacing`），因此这条偏转不进入地面力律的读数。

**相位可读性的读数。** 70 kg 圆柱从高出地面 2 cm 处落到平地并静置，100 Hz；法线朝上（`|n.y| ≥ 0.5`）的点计入，两个数分别是窄相里（`Collide.Pre` / `Collide.Processed`）读到的和与求解后枚举 manifold 得到的和：

| 步 | 窄相读数 | 求解后读数 | 说明 |
| ---: | ---: | ---: | --- |
| 0–4 | 0.0000 N·s | 0.0000 N·s | 接触点已建立（碰撞边距内），尚未真正承重 |
| 5 | 0.0000 N·s | 4.2071 N·s | 首个承重步：窄相里没有可读的历史值 |
| 6 | 4.2071 N·s | 43.8619 N·s | 落地冲击，是静置值的 6.39 倍 |
| 7 | 43.8619 N·s | 6.8670 N·s | 冲击当步读到的仍是上一步的值 |
| 8–13 | 6.8670 N·s | 6.8670 N·s | 静置，两侧都等于 `m·g·dt` |

三件事被这张表钉住：窄相里读到的和逐点等于上一步求解的和，滞后期恒为一步；首个承重步无样本，只能按 §8.3 的重力兜底；落地峰值单步 6.39 倍、经软压缩后 3.68 倍，所以缓存必须压缩后再用。另外该用例的 `conceived` 每步都触发（120 步 120 次）：静置支撑的接触点每步都会走一遍 `Collide.Pre`，摩擦写入不依赖「点是不是新建的」。

**载荷缓存的整条链。** 同一个控制器刚体、平地、100 Hz、固定双腿夹具（各 350 N／1.6–4.0–6.0 m/s，辅助为 0），测试侧按生产收集器的同一道门扫 manifold 并把和交给 `MechaCharacter#recordSupportImpulse`：

| 步 | 本步求解出的 J | 本步用的 `N_eff` | 说明 |
| ---: | ---: | ---: | --- |
| 5 | 4.2071 N·s | 686.7 N | 首个承重步仍用静态兜底 |
| 6 | 43.8619 N·s | 420.7 N | 上一步只有 0.61 倍静态载荷，低于 κ 原值进入预算 |
| 7 | 6.8670 N·s | 2529.8 N | 上一步的 6.39 倍经软压缩成 3.68 倍 |
| 8 起 | 6.8670 N·s | 686.7 N | 静置重合 |

60 步内的峰值等效载荷 2529.8 N，末步回到 686.7 N。这条读数与 §8.3 的表一致，区别是这里走的是正式控制器的 `planDrive`，判据逐步断言「本步的 `N_eff` 等于上一步的冲量经软压缩后的值」，因此它同时证明缓存被消费、压缩被应用、无样本时确实回落。

纯数学部分在常规测试类中验证负沿向速度、限幅、逐源求和、权重和导出功率；不得用生产公式的逐字复制充当测试预期。

## 14. 隔离测量的复现条件

本节使 §2.2 的读数不依赖临时源码或本机生成报告。所有测量在原点附近，步长 0.01 s；循环顺序为控制器预步、空间步进、读取结果。空间步进使用 `update(dt, 0, 0)`，不接游戏的地形回调。正式控制器使用核对基线中的实现，前馈开启；裸刚体对照不运行控制器预步。

### 14.1 持续前进

1. 构造 PhysicsSpace，重力取默认的 `(0,−9.81,0)`。对照空间边界设为每轴 ±10000 m。
2. 静态地面盒的半尺寸为 `(L,0.5,L)`，中心 `(0,−0.5,0)`，摩擦 0.5，组为 TERRAIN，掩码包含 TERRAIN 和 PAWN；分别取 L=50、5000。
3. 正式控制器使用 `common/control/attr/MechaBodyPreset.java#newBodyShape`，即半径 0.4 m、全高 2.4 m 的圆柱；默认碰撞边距。质量 70 kg，角色摩擦 2.0，出生脚底 y=0，初速度为零，yaw=0。
4. 力学配置为 `common/control/attr/MechaWalkingAttr.java#F_MAX`=700 N、`common/control/attr/MechaWalkingAttr.java#P_BASE`=800 W、`common/control/attr/MechaWalkingAttr.java#V_RATED`=6 m/s、`common/control/attr/MechaWalkingAttr.java#LAMBDA`=2 m/s、`common/control/attr/MechaWalkingAttr.java#C1`=0；前馈释放余量为 0.01。
5. 每步持续给予向 +Z 的移动输入，分别取移动倍率 1.0、0.3、0；运行 6000 步。记录 12、30、60 s 的位置、脚底高度、水平速度与着地布尔，并记录第一次从有支撑转为无支撑的时间。
6. 将 L=50、倍率 1.0 的 12 s 结果与现有 `src/test/java/io/github/sweetzonzi/arms_core/common/control/RigidBodyControllerMeasurementTest.java#measureSteadyStateSpeed` 对照。不能只比较末速而忽略是否已经跑出地面。

### 14.2 落地摩擦对照

1. 构造边界为每轴 ±500 m 的 PhysicsSpace。地面盒半尺寸 `(100,0.5,100)`、中心 `(0,−0.5,0)`、摩擦 0.5，组和掩码与 §14.1 相同。
2. 圆柱几何、质量与默认边距与 §14.1 相同；角色组为 PAWN、掩码为 TERRAIN。出生脚底高度分别取 2、5 m，初始速度为 `(0,0,6)`，yaw=0，无跳跃。
3. 裸刚体使用角因子 `(0,1,0)`。正式控制器使用自身构造配置。分别取角色摩擦 2.0、0；摩擦为零的场景仅用于定位切向损失来源。
4. 分别运行裸刚体、无输入正式控制器、持续向 +Z 输入的正式控制器，最多 200 步。
5. 每步读取预步前与预步后的速度，以及空间步进后的速度和脚底高度。把“预步后竖直速度小于 −0.5 m/s、步进后上升超过 0.5 m/s、脚底低于 0.1 m”的首次物理步作为撞地采样点。
6. §2.2 列的是 5 m 场景中的部分对照，水平速度取预步前和空间步进后。完整记录应覆盖接触后的若干步，不能把一次冲击采样称为整个落地过程的收敛结果。
