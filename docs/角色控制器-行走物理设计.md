# 角色控制器 — 行走物理设计

> **状态**: 设计草案  ·  **关联文档**: [机娘模组企划](./总体设计文档.md) 2.4 节角色运动系统

本文档细化 MechaControl 的行走物理模型，涵盖双层架构的约束隔离方案、离散状态机、基于功率-力-速曲线的多源驱动模型、跳跃蓄力冲量模型、地面抓地力模型、地形交互（爬坡限制与自动越障）以及控制器朝向定义。全文采用国际单位制。

***

## 1. 核心架构：运动学角色控制器

### 1.1 问题

传统做法将控制器胶囊实现为动力学刚体（`PhysicsRigidBody`），暴露出两个问题：

- **外部冲击耦合**：爆炸、撞击等外部力直接作用于控制器刚体 → 角色被炸飞，即使躯体还在可控范围内。
- **力驱动抖振**：应用层手工力模型（§3）与 Bullet 约束求解器各自独立处理摩擦/阻尼，两者在不同物理量级下容易产生振荡——手工刹车力在 v→0 时需要额外的 fade-out 避免来回滑动。


### 1.2 方案：`btKinematicCharacterController`（KCC）+ 手动积分

控制器不再使用动力学刚体，改用 Bullet 原生的 `btKinematicCharacterController`（通过 Spark-Core 的 `PhysicsCharacter` 封装）。

**PhysicsCharacter 是什么**：幽灵体（ghost object）。只做碰撞检测，不参与动力学模拟。内置成熟的运动学行走逻辑——sweep test、滑墙、auto-step（`setStepHeight`）、爬坡角限制（`setMaxSlope`）、着地检测（`onGround`）。

```
每物理步:

  输入 → 力模型（§3）→ F_net
      │
      ▼
  手动积分:  a = F_net / m
           v += a × dt
           v_braked = v × (1 - linearDamping)    // Bullet 内建阻尼
           Δ = v_braked × dt
      │
      ▼
  physicsCharacter.setWalkDirection(Δ)
      │
      ▼
  Bullet KCC 内部自动完成:
    · 碰撞 sweep（幽灵体对世界的 convex sweep）
    · 滑墙（命中面的切线方向运动保留，法向被拒绝）
    · 自动越障（垂直面命中 + step height 检查 → 抬高）
    · 爬坡角限制（超过 maxSlope → 按墙面处理，沿坡下滑）
    · 着地检测
      │
      ▼
  读回 KCC 解析后位置 → 作为躯干约束锚点（§1.3）
```

**关键效果**：
- **外部冲击天然解耦**：幽灵体不参与碰撞响应，爆炸力只作用于躯干刚体，不影响控制器。
- **碰撞解析在引擎内部**：sweep / 滑墙 / auto-step / slope 由 Bullet 的 `btKinematicCharacterController` 经过十几年打磨的 C++ 代码处理，零抖振。
- **我们的力模型专注于加速度**：只需 `F_net → a → v → Δ`，不必操心碰撞几何。

### 1.3 躯干跟随：世界锚点约束

控制器本身没有刚体，但躯干（含四肢的组装体）仍是**动力学刚体**。躯干通过单端世界约束（`New6Dof`，bodyA=null，A 端固定于世界坐标）牵引：

```
世界坐标系
    │
    │ New6Dof 单端约束（bodyA=null，pivotInWorld = KCC 每步解析后位置）
    │
[躯干 + 四肢刚体]           [PhysicsCharacter KCC（幽灵体，独立运动学步进）]

每步更新: setPivotInA(KCC位置)
```

躯干由约束自然随控制器，但其自身质量惯性、关节限制、外部冲击全部保留——被击中时躯干拖后产生分离距离。

### 1.4 距离保护

躯干被外部冲击击退而与控制器拉开距离时，控制器不应无感异步——施加到控制器的行走力随分离距离折减：

```
sep = |KCC.pos - torso_COM.pos|
sep_max = 可配阈值（默认 2m）
行走力 *= max(0, 1 - sep / sep_max)
```

被重击打得身体飞出去时，控制器自然被"拖住"减速。当分离距离超过阈值且持续扩大时，应触发状态切换进入 RAGDOLL（§2.4）。

### 1.5 控制器质量

质量 m 不再用于 Bullet 刚体（控制器无刚体），仅用于手动积分计算加速度：

```
a = F_net / m
```

控制器质量 = 机体总质量。惯性表现与裸机一致。质量越大 → 同驱动力下加速度越小 → 手感厚重。

### 1.6 形状切换

蹲姿/站姿切换需更改 KCC 的碰撞形状。`PhysicsCharacter.setCollisionShape()` 要求不在物理空间中：

```
// 仅在蹲/站切换时触发，频率极低
val savedPos = physicsCharacter.getPhysicsLocation(null);
physicsSpace.removeCollisionObject(physicsCharacter);
physicsCharacter.setCollisionShape(newShape);
physicsSpace.addCollisionObject(physicsCharacter);
physicsCharacter.warp(savedPos);
```

成本：Bullet 内部重建 `btKinematicCharacterController`。触发频率低（仅蹲/站），60fps 下玩家无感知。

### 1.7 控制器朝向定义

控制器的 yaw 即为躯干朝向。行走力沿躯干前方分解为世界坐标系方向后传入 `setWalkDirection`。头部朝向是客户端表现层概念，相对躯干做有限旋转，不参与角色控制器物理计算。

> 移动参照系（相机相对 / 身体相对）也属于客户端输入映射层职责，不在本文档范围内。角色控制器只接收最终映射后的 `input_direction`（世界坐标系下的水平单位向量）。

## 2. 状态机

玩家通过**离散按键**或**程序逻辑**(如布娃娃，浸入水中)在各状态间切换。状态决定 worldAnchor 的定位策略和约束行为。

```
                         ┌─────────────┐
                  toggle  │    WALK     │  toggle
              ┌───────────│ 控制器主导   │───────────┐
              │           └──────┬──────┘           │
              │                  │                  │
              │            death/硬直               │
              ▼                  ▼                  │
       ┌─────────────┐   ┌─────────────┐            │
       │    DRIVE     │   │   RAGDOLL   │            │
       │ XZ放开 Y锁   │   │  全部解锁    │            │
       └──────┬──────┘   └─────────────┘            │
              │                                      │
              └──────────── death ───────────────────┘
                        (ragdoll 也能死亡)

       ┌─────────────┐
       │    SWIM     │ ◄── 进入水体
       │   (未来)    │
       └─────────────┘
```

### 2.1 状态行为

| 状态          | 锚点世界位置.XZ (pivotInWorld) | 锚点世界位置.Y (pivotInWorld) | 约束旋转     | 说明             |
| ----------- | ------------------------ | ----------------------- | -------- | -------------- |
| **WALK**    | controller.pos           | controller.pos          | 全锁       | 控制器主导位置，身体追随   |
| **DRIVE**   | body.COM（每帧追）            | controller.pos（单向弹簧）    | 全锁（弹簧阻尼） | XZ 自由推进，Y 兜底支撑 |
| **RAGDOLL** | body.COM（0.3s过渡）         | body.COM（0.3s过渡）        | 逐渐解锁     | 完全布娃娃          |
| **SWIM**    | —                        | —                       | —        | 未来设计           |

### 2.2 WALK — 行走/站立

默认状态。约束锚点（pivotInWorld）全等于 controller.pos。施加到控制器的行走力通过单端世界约束单向传递给身体。

站立时行走力为零，控制器胶囊与身体紧耦合——自然提供抗扰动稳定性。

### 2.3 DRIVE — 高速移动

玩家按键切换。此状态下轮子（MotorSubsystem）和推进器（ThrusterSubsystem）对自身刚体施加驱动力，不再经控制器中转。

**XZ 平移**：解锁。锚点 XZ 每帧追踪 body.COM（每步调 `setPivotInA()` 更新），躯体不受控制器拖累。

**Y 轴**：单向弹簧约束。仅当身体 Y 低于锚点 Y（即低于控制器所在高度）时施加回拉力——控制器兜底支撑。控制器胶囊被斜坡/台阶碰撞抬升时锚点 Y 自然上移，无阻力。身体越障弹起时无向下拽力。

**Y 轴跳跃行为**：玩家在 DRIVE 下按跳跃键时，Y 轴临时切换为双向传力（持续 \~0.5s），跳跃完成后恢复单向弹簧。

**旋转轴**：全锁，弹簧阻尼（ERP=0.8, CFM=1e-5）。维持直立但允许 ±2° 微倾吸收颠簸。机体自然跟随控制器的面朝方向，无需复杂的车控逻辑。

### 2.4 RAGDOLL — 布娃娃

死亡/腿部全毁时进入。锚点渐变（0.3s）从控制器位置过渡到 body.COM，之后平移和旋转约束全部解除，身体自然 ragdoll。

### 2.5 状态切换渐变

```
WALK → DRIVE:
  锚点 XZ: controller.pos → body.COM.pos（0.5s lerp）
  锚点 Y:  controller.pos（不变）

DRIVE → WALK:
  锚点 XZ: body.COM.pos → controller.pos（0.5s lerp）
  锚点 Y:  controller.pos（不变）
```

进入 DRIVE 时约束平移刚度同步从正常值下降到零（XZ 解锁），退出时反向。渐变时长硬编码 0.5s。

## 3. 行走驱动力模型

### 3.1 概念综述

行走驱动由多个**动力源**组成：控制器本体（素体"肌肉"）加上各腿部助力子系统（LocomotionLimbSubsystem）。每个源独立基于功率-速度关系出力和自限速，最终合力经地面摩擦钳制后施加到控制器胶囊。

### 3.2 动力源参数

每个动力源拥有三个核心参数：

| 参数   | 符号       | 单位  | 含义                      |
| ---- | -------- | --- | ----------------------- |
| 功率   | P        | W   | 持续机械输出功率                |
| 额定速度 | v\_rated | m/s | 有效工作速度上限，超速则出力衰减        |
| 最大出力 | F\_max   | N   | 低速区间（v→0）的力上限，同时约束极限加速度 |

### 3.3 力-速曲线（每物理步计算）

水平对地速率 v = |velocity\_horizontal|

**第一步：功率限力**

```
F_power = P / v   （v > ε）
F_power = F_max   （v ≈ 0，用 F_max 兜底避免除零奇异）
```

**第二步：力上限钳制**

```
F_raw = min(F_power, F_max)
```

起步时 v→0 导致 F\_power→∞，F\_max 钳制防止无限大力和加速度发散。

**第三步：超速衰减**

```
当 v ≤ v_rated：F = F_raw
当 v > v_rated：F = F_raw × exp(-(v - v_rated) / λ)
```

λ（衰减陡度）可配，默认合理值。超过额定速度后该源快速退场。让"高扭低速"源在起步区主导，"高速"源在极速区接棒。

### 3.4 多源叠加

物理步进时，收集所有活跃源：

```
F_drive_total = Σ F_i    （i = 控制器本体 + 所有 LocomotionLimbSubsystem）
```

各源依自身 P / v\_rated / F\_max 独立计算 F\_i，各对速度区间形成自然分工——无需手动权重分配。

**控制器本体**的 P\_base / v\_rated / F\_max 定义于 `mech_chassis.json`。助力子系统各自定义于腿部 Part JSON。

### 3.5 地面抓地力限制

所有驱动合力最终都通过脚-地面接触传递。因此总驱动力受静摩擦约束：

```
F_drive_effective = min(F_drive_total, μ × N)
N = m × g × cos(θ_slope)
```

μ 取所有活跃 LocomotionLimbSubsystem 中 `μ_foot` 的**最大值**。多足时取最好那只脚的抓地力。若未安装任何助力腿，退化到素体裸足摩擦系数 `μ_naked`（定义于 mech\_chassis.json）。

**摩擦系数来源**：仅来自助力子系统属性，与 Machine-Max 碰撞箱 friction 不混用。μ\_foot 代表脚底最大静摩擦，语义独立。

> **与 KCC 内建碰撞的关系**：§3.5 的抓地力限制 `min(F_drive_total, μ × N)` 是应用层钳制——确保驱动力不超物理极限。KCC 自身的 `setMaxSlope` 和碰撞响应提供额外的运动学保障。有输入时 `setMaxSlope = atan(μ_effective)`（每步动态更新），过量坡度下 KCC 拒斥法向运动。

### 3.6 内阻与净力

```
F_resist = c₀ × m × g
F_net = F_drive_effective - F_resist - m × g × sin(θ_slope)
```

**内阻系数 c₀**（无量纲）：由设计参数自动导出，不手工配置。

```
c₀ = P_base / (v_ref × m_naked × g)
```

其中 P\_base 为控制器本体基准功率，v\_ref 为期望裸机行走速度，m\_naked 为裸机质量。c₀ 在素体加载时计算一次，之后作为该素体的"生物力学效率常数"保持不变。

加装零件使总质量 m 增大 → 内阻力 c₀ × m × g 增大 → 同功率下匀速更低，实现"越重越慢"。助力子系统增加功率 → 驱动力增大，平衡更高速度。

**粘滞阻尼**：一阶速度相关项 `c₁ × v` 不在此处计算，而是通过 `physicsCharacter.setLinearDamping(c₁)` 映射为 KCC 内建线性阻尼，在运动学步进阶段自动消耗速度。阻尼是纯阻力——它只消耗速度，不像摩擦力（μ × N）能提供反力——因此不应出现在牵引力竞争链路中。

> F\_resist 仅在**有行走输入时**施加（此时 `v_horizontal > 0` 且 `a > 0`）。无输入时仅 KCC 线性阻尼和碰撞摩擦制动（§3.9）。

### 3.7 空中行为

离地时（N=0，无地面接触）：

```
F_drive_effective = F_drive_total × 0.05
```

控制力衰减至 5%，允许空中姿态微调但不可加速。硬编码系数。

### 3.8 位移生成与施加

行走力最终以位移增量形式传入 KCC。每物理步：

```
v_horizontal = |physicsCharacter.getLinearVelocity()|_horizontal   // 从 KCC 读取实际水平速率

有输入时：
  a = F_net / m                            // 水平加速度（§3.6）
  v_horizontal += a × dt                   // 速度积分
  // KCC 线性阻尼（c₁）在此处消耗速度——physicsCharacter.setLinearDamping(c₁) 内部处理
  Δ = v_horizontal × dt × input_direction  // 本步位移向量
  physicsCharacter.setWalkDirection(Δ)     // 水平位移传入 KCC

无输入时（§3.9）：
  // 主动摩擦刹车（§3.9），不叠加加速度
  Δ = v_horizontal × dt
  physicsCharacter.setWalkDirection(Δ)

KCC 每步内部:
  1. 对 walkDirection 施加线性阻尼（c₁）
  2. Δ 叠加重力到垂直分量
  3. convex sweep 检测碰撞
  4. 滑墙（切向保留，法向拒绝）
  5. auto-step 越障（≤ stepHeight 的垂直面）
  6. 爬坡角限制（> maxSlope → 按墙面处理）
  7. 着地检测 → 更新 onGround
```

> `setWalkDirection(Vector3f)` 传入的是**每物理步的位移增量**（单位 m/tick），不是速度。KCC 按此偏移量执行 sweep 并解析碰撞。垂直分量始终为 0——重力加速度和着地由 KCC 内部接管。
>
> `v_horizontal` 从 KCC `getLinearVelocity()` 读取而不再自维护跨步积分变量——KCC 阻尼和碰撞解析后的实际速度即为下一积分步的基础。

### 3.9 无输入制动

无行走输入时（input\_direction ≈ 0），不施加驱动力，依靠**主动摩擦刹车**配合 KCC 阻尼减速。摩擦刹车模拟角色"主动停步"——脚底施加最大静摩擦以尽快站住，不同地面表现不一：

```
若无输入：
  F_drive_total = 0
  F_net = 0
  a = 0
  a_brake = μ_effective × g × cos(θ_slope)        // 摩擦刹车减速度，与质量无关
  v_horizontal -= a_brake × dt                     // 每步减速
  if (v_horizontal < 0) v_horizontal = 0
  // KCC 线性阻尼（c₁）叠加提供一阶速度衰减
  Δ = v_horizontal × dt                            // 沿当前实际速度方向
  physicsCharacter.setWalkDirection(Δ)
```

**两条减速线分工**：

| 机制 | 来源 | 触发条件 | 效果 |
| ---- | ---- | -------- | ---- |
| 摩擦刹车 | μ\_effective × g × cosθ | 无输入时 | μ=1 急停，μ=0.05 长滑 |
| 粘滞阻尼 | physicsCharacter.setLinearDamping(c₁) | 始终生效 | 空气阻力级持续衰减 |

> 摩擦刹车减速度 `μ × g` 与质量无关（`a = (μ × m × g) / m = μ × g`），刹车手感仅由地面 μ 决定，不受机体重量影响。

> 注意：即使无输入，滑坡（θ\_slope > 0）时重力分量 `m × g × sin(θ_slope)` 未在水平力模型中扣除？已在 §3.6 中扣除。但 KCC 内部重力仍会使胶囊沿坡下滑——`setMaxSlope` 限制了"可站住"的最大坡度（= atan(μ_effective)，§8.1）。

## 4. 跳跃模型

### 4.1 概念

跳跃是瞬时过程，以冲量建模。每条助力腿提供自身的 I\_min / I\_max / v\_extend。素体裸身跳跃参数由 mech\_chassis.json 兜底。

### 4.2 参数

| 参数     | 符号        | 单位  | 位置    | 含义            |
| ------ | --------- | --- | ----- | ------------- |
| 轻拍冲量   | I\_min    | N·s | 腿部子系统 | 轻按跳跃键的冲量      |
| 满蓄冲量   | I\_max    | N·s | 腿部子系统 | 蓄满后施放的冲量      |
| 最大伸展速度 | v\_extend | m/s | 腿部子系统 | 单腿可贡献的起跳速度硬上限 |
| 满蓄时间   | t\_charge | s   | 控制器   | 从轻拍到满蓄所需的按住时长 |

### 4.3 蓄力机制

线性蓄力曲线：

```
ratio = min(t_hold / t_charge, 1.0)
I_per_leg = I_min + (I_max - I_min) × ratio
```

按住跳跃键累积 t\_hold。松开即施放当前 ratio 对应的冲量。

### 4.4 蓄力期间的行为

| 行为        | 处理                                                     |
| --------- | ------------------------------------------------------ |
| 移动输入      | 行走速度随 ratio 折减：`v_walk_multiplier = 1.0 - ratio × 0.5` |
| 转向        | 不受影响                                                   |
| 松开跳跃键     | 立即按当前 ratio 施放冲量                                       |
| 受击/硬直/中断  | 蓄力取消归零，不触发跳跃                                           |
| 离地（脚脱离地面） | 蓄力取消                                                   |

### 4.5 多腿叠加与起跳速度硬上限

```
I_vertical = Σ I_per_leg_i      （各腿冲量叠加）
v_raw = I_vertical / m           （理论垂直离地速度）
v_takeoff = min(v_raw, max(v_extend_i))
```

取最快那条腿的 v\_extend 作为硬上限——最快腿伸直时身体已离地，慢腿来不及继续发力。

### 4.6 方向冲量与抓地力

方向跳（前跃/侧跳）有水平分量。水平冲量受抓地力约束：

```
I_horizontal_effective = min(I_intended_horizontal, μ_effective × I_vertical)
```

垂直跳时无水平分力，不受摩擦限制。前跃在冰面（μ≈0.05）被压至几乎纯垂直跳；粗糙地面可做出远距跳跃。

### 4.7 施加

KCC 内置跳跃机制可直接复用——设置起跳速度后调用 `jump()`，水平速度自动保留：

```
physicsCharacter.setJumpSpeed(v_takeoff)
physicsCharacter.jump()
```

> KCC 的 `jump()` 内部将垂直速度覆写为 `m_jumpSpeed` 同时保留水平分量，无需手工构造 `setLinearVelocity` 向量。方向跳（前跃/侧跳）的水平冲量可通过 `jump(Vector3f direction)` 传入。

新增子系统类型。继承 Machine-Max 的 `BasicSubsystem`，不侵入 Machine-Max 代码。

## 7. 与轮子/推进器的边界

- **WALK 状态**：轮子（MotorSubsystem）不施加驱动力。推进器（ThrusterSubsystem）可工作（为超高空爆发/多段跳预留入口，视设计需要）。
- **DRIVE 状态**：轮子按现有车辆逻辑驱动自身 SubPart 刚体，推进器施力于躯干。两者的推进力不经过控制器，不参与行走合力计算。控制器仅通过旋转约束维持直立。

## 8. 地形交互

### 8.1 爬坡角度限制

最大可攀爬坡度由物理导出，无需额外配置参数：

```
θ_max = atan(μ_effective)
```

其中 μ\_effective 取所有活跃 LocomotionLimbSubsystem 中 μ\_foot 的最大值（同 §3.5）。此限制由现有驱动力模型自然实现：

- §3.5 抓地力限制：F\_drive\_effective ≤ μ × N = μ × m × g × cos(θ\_slope)
- §3.6 重力分量：F\_net 中扣除 m × g × sin(θ\_slope)

当 θ\_slope → θ\_max 时，抓地力上限趋近于重力下滑分量，净驱动力趋零。超过 θ\_max 后抓地力不足以对抗重力，控制器沿坡面下滑。μ\_foot 越高 → 爬坡能力越强，纯物理自洽。

### 8.2 自动越障（Auto-Step）

小型垂直障碍（半砖、台阶边缘、地毯）不应卡住角色。每物理步执行越障检测：

```
1. 水平 sweep：沿 input_direction 向前 sweep 一个步长
2. 若命中垂直面（法线接近水平）：
   a. 在命中点上方 step_height_effective 处再次水平 sweep
   b. 若上方通道畅通且落脚面深度 ≥ step_depth_min：
      → 控制器胶囊瞬移抬高，继续水平移动
   c. 若上方也堵塞 → 正常碰撞停止
3. 若未命中垂直面 → 不触发越障
```

**生效步高**：

```
step_height_effective = step_height_base + max(各腿部子系统的 step_height_bonus)
```

默认 0.6m（能上半砖/地毯，上不了完整方块），腿部升级后可提高。取所有腿中最大加成——用最好的那条腿跨障碍。

### 8.3 参数

| 参数               | 默认值  | 来源                 | 说明                    |
| ---------------- | ---- | ------------------ | --------------------- |
| `step_height`    | 0.6m | mech\_chassis.json | 素体裸足越障高度              |
| `step_height`    | 0m   | 腿部 Part JSON       | 单腿越障加成                |
| `step_depth_min` | 0.2m | 硬编码                | 障碍顶面最小可站立深度，防止跨步后卡进墙内 |

> θ\_max 由 μ\_foot / μ\_naked 导出，不暴露为独立配置项。
